# juicebar

把无线键鼠的电量常驻在 Windows 任务栏，**不必打开厂商的 hub**。

## 为什么

三模键鼠走蓝牙时 Windows 自己能显示电量，走 2.4G 接收器时不行——想看精确电量只能打开厂商上位机，还得点进具体设备。juicebar 直接跟接收器对话，把数字放进托盘。

## 现在能做什么

双击 `juicebar.exe`，任务栏里出现一个画着电量的图标：悬停看 Primary Device 的名字、电量、来源和多久前；右键看每台设备一行、换托盘上画哪一台、改图标样式、登记设备、开关开机自启。跌破低电阈值时弹一条通知。进度见下方"状态"。

## 设计要点

- **托盘单图标**，画一个可配置的主设备的电量数字。默认主设备是"当前电量最低的那个"——这个工具是为了别让设备突然没电，钉死某一个意味着另一个的风险你依然看不见。
- **图标怎么画由用户选**：画法（纯数字 / 电池 / 圆环 / 数字+底条）、字形、满电怎么画、灰状态怎么区分等 8 项都是设置。缺省是"数字+底条"——数字始终是最高对比色，低电的红、充电的绿交给底下那条。设计稿在 [`.scratch/tray-design/icon-review.html`](.scratch/tray-design/icon-review.html)，取舍见 [`docs/adr/0005`](docs/adr/0005-tray-icon-style-is-user-configurable.md)。
- **左右键弹原生菜单**列出全部设备，零 GUI 框架。图标样式也在这个菜单的子菜单里改，不开设置窗口；每个选项前面挂一张按托盘真实尺寸画的预览小图。
- **两条数据来源区别对待**：2.4G 是当场问出来的实时值，蓝牙是 Windows 攒的缓存（可能过期几个月）。界面上必须能分辨，否则会在最需要它的时候给出假的安全感。
- **驱动是代码，绑定是配置**：每个协议家族一个模块实现同一个 trait；"哪个 VID/PID 走哪个驱动、开哪个 collection"写在配置里。加一个新品牌 = 加一个文件。
- **读到的数要过合理性校验**，校验不过就报"读取异常"而不是显示荒谬数字。协议是从上位机逆出来的，厂商推个新固件就可能失效。

## 构建

```
cargo build --release
```

需要 MSVC 工具链。仅 Windows。产物是 `target\release\juicebar.exe`。

## 用法

**双击 `juicebar.exe` 就是托盘。**它只有这一个样子，没有命令行子命令，带不带参数启动都一样（[`docs/adr/0008`](docs/adr/0008-no-command-line-in-the-product.md)）。

- **手动启动会弹 UAC**：程序带着要求管理员权限的程序清单，走 2.4G 取数非管理员不可（见下）。框里写"未知发布者"，因为没有代码签名。
- **开机自启在右键菜单里**：勾上"开机自启"，程序建一个登录时以最高权限运行的计划任务，开机不弹 UAC；取消勾就删掉它。缺省不开（[`docs/adr/0007`](docs/adr/0007-elevated-manifest-and-scheduled-task-autostart.md)）。
- **再启动一次不会冒出第二个图标**：已经在跑的那一个弹一句"已经在托盘里了"，新的这个自己退出。
- 右键菜单里还有"托盘上画哪一台"（自动选电量最低的，或者钉死某一台）、"图标样式"、"菜单显示"、"登记设备"、"打开配置文件"、"退出"。

### 配置

配置在 `%APPDATA%\juicebar\config.toml`，日志与状态文件在它旁边。

**首次运行没有配置文件时会自动扫描并生成一份草稿**，能猜的先猜、猜不动的留成注释，并弹一条通知叫你右键"打开配置文件"看一眼。改了配置文件不必重启，程序自己重读；改坏了照旧用上一份读好的，菜单最顶上说一句读不了。

草稿里**注释掉的块**是程序猜不动、或者生成那一刻扫不到的东西——最常见的是 `[device.wired]`，它只在插着线时才枚举得到（键盘还要把机身模式开关拨到有线档）。**插上之后程序会自动补上**空着的那一块，并弹一条通知；你手写过的值和注释一概不动。蓝牙地址程序猜不出来：到右键菜单"登记设备"里，把本机扫到的那台登记到对应的 Device 上，或者直接新建一台 Device。

### ⚠ 走 2.4G 取数为什么要管理员

非管理员时 Windows 会把发给接收器的写**静默吞掉**——句柄开得到、API 全部返回成功、读也正常，
但设备根本收不到。结果是那一行报「读超时」或者「dongle 报未就绪」，**看起来像设备没插、没配对
或者睡着了**，而真正的原因在这儿。同一台机器上实测：非提权读超时，提权首读就拿到 `94% / 4076 mV`。

托盘带着程序清单，撞不上它；下面的诊断示例程序不带清单，会撞上。蓝牙那条路不需要管理员。细节见
[`docs/protocol.md`](docs/protocol.md) 第 3 节。

### 诊断工具（做协议逆向用）

诊断工具是示例程序，不进发布构建，从源码树里跑，参数写在 `--` 后面：

```
cargo run --example scan              # 列出所有 HID collection 和带电量属性的 BLE 设备（-- --all 连不含厂商通道的也列）
cargo run --example caps -- ...       # 打印一条 collection 声明的 Report ID，不向设备发任何字节
cargo run --example probe -- ...      # 向指定 collection 发原始帧并打印回包（支持 --vgn-keyboard-crc、--reads、--watch、--parse）
cargo run --example neon75_probe --   # Neon75 专用抓包调试工具（query 连通性测试 / diff-watch 差分抓包 / send / verify-offline）
```

**在管理员终端里跑。**它们不带程序清单，从没提权的终端里跑，`probe` 发给 2.4G 接收器的帧会被上面那样静默吞掉，看起来就是读超时；只枚举、不发帧的 `scan` 在普通终端里也行。

## 已知限制

**Windows 11 默认把新出现的托盘图标折叠进溢出区**（那个 `^` 箭头里），没有公开 API 能让程序自己跳出来。第一次运行后请手动把它从溢出区拖到任务栏上，拖一次就永久记住了。这是所有托盘工具的共同处境。

**VGN HUB 在跑时 2.4G 轮询会暂停**（图标标灰、保留最后读数），避免两个程序抢同一条 HID 通道导致响应串台。反正那几分钟你在 HUB 里也能看到电量。

## 支持的设备

| 设备 | 2.4G | 蓝牙 |
|---|---|---|
| VGN Dragonfly 3 Master+ | ✓ 实测可读（程序以管理员身份运行时） | ✓ |
| VGN Neon75 | ✓ 实测可读 | ✓ |
| 任何 BLE 设备 | — | ✓（只要 Windows 缓存了电量属性；在"登记设备"里新建一台 Device） |

**Neon75 2.4G 协议已彻底收口（2026-09-16）**：通过真机 USB 抓包与 VGN Hub 源码对齐，查明此前所谓的"就绪位恒为 0"实为有效回报（首字节本来即为 `0x00`，电量在 `frame[1]`，休眠位在 `frame[3]`）。修复解析逻辑后，真机实测首读直接秒读命中 98%。

ATK、雷柏等后续接入。协议细节见 [`docs/protocol.md`](docs/protocol.md)。
