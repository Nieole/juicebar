# 03: "这一轮的结果"成形，低电阈值第一次生效

**What to build:** 把"这一轮"从命令行里提出来，变成一个测得到的纯函数交出来的结构：每台 Device 的
**图标状态**（按 `CONTEXT.md` 的优先顺序）、电量（有的话）、来源 Endpoint、多久前、一句短原因；
Primary Device 是谁、怎么选出来的（钉死 / 自动 / 保持上次的选择）；这一轮的告警。托盘内核（票 04）
要的就是它——它取代 `screen-as-a-function` 的票 03，只是换了唯一的用户。

**低电阈值今天只存在于文档里**：`low_battery` 写在 `config.example.toml` 和草稿里，注释说"可被单个
`[[device]]` 覆盖"，但程序从来不读它——schema 里没有这个字段，被静默忽略。图标状态里的"低电"
就靠它，所以本票让它第一次生效。

命令行在过渡期**从这个结构排版，输出一个字不变**——这是"提取得对不对"最硬的判据。

**Blocked by:** None (can start immediately) —— 会和 `screen-as-a-function` 票 04（取数失败那个变体
改名）碰同一个枚举：两张先后都行，后落地的那张跟着对齐名字。

**Status:** ready-for-agent

- [ ] 结构如上，由一个纯函数产出；输入是配置、各台 Device 这一轮手上有的东西（一次取数的结果或
      上次已知值、暂停与否）以及"当下"
- [ ] 图标状态的优先顺序：暂停 > 取数失败 / Unknown / 无已知值 > 充电中 > 低电 > Stale > 正常；
      **低电压过 Stale**：上次已知值低于阈值，即使已经 Stale 也算低电
- [ ] `low_battery` 进 `[general]`（缺省 20），单台 `[[device]]` 可以覆盖；缺席用缺省值
- [ ] **进程枚举失败时按"没在跑"走**（fail open），并作为这一轮的一条告警交出来——反过来会让一台
      Win32 调用失败的机器永久显示暂停、指名一个没在跑的进程。第 1 趟 `/settle` 的 Q34 记着这条
      规则测不到，从本票起有用例（从 `screen-as-a-function` 票 03 接过来的）
- [ ] 命令行那几行改从这个结构排出来，**现有的排版用例一条不改、全绿**
- [ ] 新增用例覆盖优先顺序的每一处边界：至少低电 × Stale、充电中 × 低电、暂停 × 其余每一种、
      无已知值；外加单台阈值覆盖
- [ ] 代码、文档与用户看得见的文字里的"这一趟"，按 `CONTEXT.md` 改成"一轮"或"一次取数"
      （包括命令行那两句 stderr——它们成了这一轮的告警）
- [ ] `config.example.toml` 里 `low_battery` 那句"图标数字变红"改成与画法无关的说法：按 ADR-0005，
      颜色与符号由图标设置决定
- [ ] gate 三条全绿
