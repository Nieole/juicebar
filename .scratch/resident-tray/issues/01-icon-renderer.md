# 01: 图标渲染器按设计稿把图标画成位图

**What to build:** 托盘上那个 16 像素的图标有了 Rust 版的画师，而且它画出来的每一个像素都能拿去和
定稿的设计稿对照。输入是图标设置（ADR-0005 八项里管图标的六项）、图标状态、电量、尺寸、调色
（深 / 浅），输出一张位图。它是纯函数，不碰 Win32 界面、不碰设备——托盘那条贯穿的线（票 04）
和两个设置子菜单里的预览位图（票 07）都用它。

**有两处做不到逐像素，这一票要把它们处理干净**：C 圆环的弧线在设计稿里是浏览器的抗锯齿画的，
"系统字体"是浏览器的文字光栅化画的——Rust 这边无论用什么实现，都不会和浏览器逐像素一致。所以
圆环改用一个两边照抄的确定性画法（设计稿先改、再导基准）；系统字体走 Windows 的文字渲染，这一项
豁免逐像素比对。

**Blocked by:** None (can start immediately) —— 与票 02、03 一个文件都不相交，三张可并行。

**Status:** resolved

- [x] 纯函数：设置、图标状态、电量、尺寸、调色 → 位图，无副作用
- [x] 四个画法、三种字形、满电的三种画法、灰状态的三种区分、没有读数时的四种符号、充电标记的三种，
      全部照设计稿的渲染器：像素字形（粗块 3×5、细体 5×7）、各画法在各尺寸上的几何、调色板、
      闪电与程序图标的位图
- [x] 设计稿里已知的两处行为照搬：B 电池在 16、20 像素不画数字；闪电占掉左侧一条，在 D 里不压到底条
- [x] 尺寸 16 / 20 / 24 / 32；显示缩放落在别的档时取最近的一档——这个判定也在这里，是纯函数
- [x] **圆环改成确定性画法**：设计稿与 Rust 用同一个算法（不依赖浏览器的抗锯齿），设计稿先改、
      再导基准
- [x] **设计稿加一个"导出基准"的入口**，导出成文本网格：一个像素一个字符，字符对应调色板里的一格
- [x] 基准覆盖面：缺省设置下 8 个图标状态 × 4 个尺寸 × 2 种调色；再对每一项设置，从缺省出发只改那
      一项、每个取值各一组。**不做全组合**
- [x] 基准比对失败时，用例打印两张网格的差异，读得出是哪几个像素不对
- [x] **系统字体那一项走 Windows 的文字渲染，豁免逐像素比对**：它的用例只断言结构——字放得下、
      居中、没有被截断、确实画了东西。在 ADR-0005 那条"Rust 画出来的每一档都应当与设计稿逐像素
      对得上"后面注明这个例外及其理由
- [x] gate 三条（`fmt --check`、`clippy --all-targets -D warnings`、`test`）全绿
