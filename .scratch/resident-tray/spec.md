# 常驻托盘

Status: ready-for-agent

术语一律按 `CONTEXT.md`（Device / Endpoint / Reading / 一次取数 / 一轮 / Stale / Unknown / 读取异常 /
上次已知值 / 失联 / 取数失败 / 暂停 / Primary Device / 图标状态 / 保持上次的选择）。相关决策：
`docs/adr/0001`（有线是一等 Endpoint）、`0002`（电量来源）、`0003`（格式保留回写）、`0004`（坏帧的
有界沉默）、`0005`（图标怎么画全部交给用户选）。设计稿 `.scratch/tray-design/icon-review.html`
（2026-09-10 定稿）。

出处是 2026-09-10 那次 `/grill-with-docs`"到目标完成还剩下的工作"，定了 15 个问题。
**本 spec 取代 `screen-as-a-function` 的票 01 与 03**；那一批的票 02、04、05 照旧有效（见
Implementation Decisions 末节）。

## Problem Statement

README 第一句是目标：**把无线键鼠的电量常驻在 Windows 任务栏，不必打开厂商的 HUB。** 今天离它还差
整整一个托盘，而且每差一样，都落在用户最需要它的时候：

**一、没有托盘。** 程序只有命令行子命令，读一次就退出。想看电量，得开一个管理员终端敲命令。

**二、走 2.4G 要管理员权限，而权限不够时看起来像硬件故障**（`docs/gaps.md` 第一条）：句柄开得到、
API 全返回成功，那一行说的却是"读超时"。

**三、插线充电时读不到鼠标。** 鼠标一插线就切到有线传数据、dongle 那一侧超时（`docs/protocol.md`），
而草稿里有线那块是注释掉的，提示用户"去跑 `juicebar config-refresh`"。恰好在"充电中"最该显示的
时候，读数没了。

**四、键盘只能靠 Ble，而 Ble 的地址得手抄。** 键盘走 2.4G 读不到，而且可能从来没真正工作过
（`docs/gaps.md`）。身份表里没有 BLE 身份，配置草稿填不出它的地址，用户得从 `scan` 的输出里抄 MAC。

**五、首次运行一台设备都没插，会走进死角**（`docs/gaps.md`）：之后插上什么，都补不进配置。

**六、菜单该有的按钮还不存在。** 手动切换 Primary Device 按不到（用户故事 17 是空的）；切回
"自动（电量最低）"写不回配置。

**七、"低电"只存在于文档里。** `low_battery` 写在 `config.example.toml` 和草稿里，注释说"图标数字
变红""可被单个 `[[device]]` 覆盖"——**但程序从来不读这个键**：schema 里没有这个字段，被静默忽略。
这是写这份 spec 时查出来的，它在文档里存在了整个 `battery-readout` 周期。

## Solution

一个程序 `juicebar.exe`，就是托盘图标：

1. **启动就拿到读 2.4G 所需的权限**：手动启动弹 UAC；勾上开机自启后，开机不弹。
2. **常驻轮询**：每台 Device 按自己当下走的那条 Endpoint 的节奏取数；任一台有了新结果就是新的一轮，
   选出 Primary Device，按用户的图标设置（ADR-0005）画出它的图标状态。悬停就看到名字、电量、
   来源和多久前。
3. **右键菜单**：每台 Device 一行；能切 Primary Device、改图标设置（每个选项带预览）、登记设备、
   开关开机自启、打开配置文件、退出。
4. **跌破低电阈值时**，每次跌破弹一次系统通知。
5. **配置自己跟上**：本机出现认得的 Endpoint、而配置里那块空着时自动补上；首次运行自动生成草稿。
6. **命令行不再是产品的一部分**；诊断工具留作开发者用的示例程序。

## User Stories

### 启动与常驻

1. 作为用户，我想双击一个程序就让电量出现在任务栏，这样我不必开终端敲命令
2. 作为用户，我想程序一启动就拿到读 2.4G 所需的权限，这样我不会看到一句"读超时"、以为设备坏了
3. 作为用户，我想在菜单里勾一下就开机自启，这样我不必每天开机都记得去开它
4. 作为用户，我想开机自启时不弹 UAC，这样开机不被打断
5. 作为用户，我想不小心再启动一次时它告诉我"已经在托盘里了"，而不是再冒出一个图标，这样托盘里
   不会有两个一样的图标、两份轮询互相抢通路
6. 作为用户，我想点"退出"就真的退出、不再轮询，这样我能随时让它让开

### 图标

7. 作为用户，我想托盘图标画的是 Primary Device 的状态，这样我一眼就知道最需要关心的那台怎么样了
8. 作为用户，我想图标在 16 像素上也看得清数字，这样 100% 缩放的屏幕也能用
9. 作为用户，我想图标跟着任务栏的深浅色换调色，这样两种主题下都看得清
10. 作为用户，我想改显示缩放、或者把任务栏挪到另一块屏幕时，图标按新尺寸重画，这样它不会糊
11. 作为用户，我想低电时图标换成低电的样子（颜色与符号按我的设置），这样我知道该充电了
12. 作为用户，我想正在充电的设备不被标成低电，这样我已经在处理的事不会一直催我
13. 作为用户，我想一台读不到了、而上次读到的是低电的设备照样标成低电，这样它没电关机时我不会错过提醒
14. 作为用户，我想暂停时图标告诉我是暂停，而不是坏了，这样我知道该去关 HUB

## Implementation Decisions

### 成品形态

- **只有一个程序，就是托盘，不带命令行。** 程序清单要求管理员权限（手动启动弹 UAC）。
- 诊断工具（`scan`、`probe`、`caps`、`probe --listen`）挪成开发者用的示例程序，发布构建不含它们。
  它们照旧只调用库的公开面。
- 命令行里 `status` 与 `config-refresh` 的活由托盘接手：设备行变成菜单行；首次运行的草稿与补空块
  见下文。命令行那一层连同它的排版用例一起退掉。

### 开机自启、单实例、日志

- **开机自启走计划任务**：登录时触发，"以最高权限运行"，所以开机不弹 UAC。菜单里"开机自启"勾上即
  建任务，取消即删；缺省不开。**这推翻了 `battery-readout` spec 里"注册表 Run 键"的计划**：需要
  提权的程序，Windows 登录时不会从 Run 键启动它。
- **单实例**：一个具名互斥体。第二个实例发现已有实例，就让老实例弹一条"已经在托盘里了"，自己退出。
- **日志**：写在配置文件旁边的一个文件里，限制大小、滚动覆盖。完整的取数失败原因、自动补配置、
  登记与解除、配置读坏，都进日志。

### 托盘内核（新，主要的那道缝）

- **纯粹的"事件进、动作出"**，不碰 Win32 界面、不碰真硬件：
  - 事件：时钟走到了；某台 Device 的一次取数有了结果；配置读到了（或读坏了）；本机设备变了（插拔）；
    用户点了菜单里的某一项；任务栏深浅色或显示缩放变了；有第二个实例来敲门
  - 动作：对某台 Device 做一次取数；按给定参数重画图标；更新菜单模型与悬停提示；弹一条通知；
    往配置里写一处改动（新文本由配置那道缝生成）；写一条日志；存状态文件
- **它交出"这一轮的结果"，而且是结构化的**：每台 Device 的图标状态、电量（有的话）、来源 Endpoint、
  多久前、一句短原因；Primary Device 是谁、怎么来的（钉死 / 自动 / 保持上次的选择）；这一轮的告警。
  菜单行与悬停提示的文字都从它排出来。这就是票 03 原本想要的那道缝，只是换了唯一的用户。
- **一次取数本身不在内核里**：内核只决定"去读哪台"，读由现有的取数那一层做，暂停也照旧在那一层。
- 上次已知值与上一轮的 Primary Device 照旧存在配置旁边的状态文件里；内核决定何时存，外壳去写。

### 图标状态与优先顺序

- 按 `CONTEXT.md`「图标状态」：**暂停 > 取数失败 / Unknown / 无已知值 > 充电中 > 低电 > Stale > 正常**。
- 低电判据是该 Device 的低电阈值。上次已知值低于阈值、即使已经 Stale，也按低电画。

### 低电阈值（schema 新增）

- `low_battery` 进 `[general]`（缺省 20），单个 `[[device]]` 可以覆盖——正是 `config.example.toml`
  已经写着的样子，第一次让它生效。

### 低电通知

- **任何一台已登记的 Device**（不只是 Primary Device）的一次取数读到低于它自己阈值的电量、而此前
  没有为它提醒过，就弹一条通知。之后读到不低于阈值、或者读到充电中，才重新武装。
- "提醒过"只记在内存里：程序重启算新的开始，仍然低电就再提醒一次。
- 拿上次已知值顶上的那种结果不触发新提醒（它不是新消息），但图标照样按低电画。

### 轮询节奏

- 每台 Device 按**它上一次取数拿到读数的那条 Endpoint** 的间隔走（`poll_interval_wired` /
  `poll_interval_24g` / `poll_interval_bluetooth`）。还没读到过的，按它配置里优先级最高的那条
  Endpoint 的间隔。
- 任一台的一次取数有了结果，就开始新的一轮（`CONTEXT.md`「一轮」）。
- 暂停检测照旧：每次取数之前问一次本机进程。

### 配置的读与写

- 每次取数前看一眼配置文件变没变，变了就重读。**读坏了就沿用上一份读好的**，菜单最顶上多一行说明
  读不了，完整原因进日志。
- `[tray]` 表按 ADR-0005 的 8 个键与取值；缺席用缺省值；取值认不出来按缺省值处理并记日志，不让整份
  配置读不动（与 `primary` 写错时的处置一致）。
- `pin_primary` 扩成也能写 `"lowest"`。
- 所有写入按 ADR-0003 格式保留：只动目标那一处，注释一句不丢。

### 自动补空块（接手 `config-refresh`）

- 本机出现一条身份表认得的 Endpoint、而它所属那台 `[[device]]` 里那一块空着（缺席，或者只有草稿
  留下的注释占位），就补上。只填空块，**不新增 `[[device]]`**（新增只能由用户在菜单里点，见下文）。
- 补了就记日志，并弹一条通知说补了哪台的哪条：配置变了，用户该知道。
- 启动时检查一次，本机设备插拔时再检查。
- 草稿里"弄好之后跑 `juicebar config-refresh`"的提示改成"插上之后程序会自动补上"。

### 首次运行

- 没有配置文件：生成草稿（现有的草稿生成），弹一条"已生成配置，右键'打开配置文件'看一眼"，然后
  照常开始轮询。

### 菜单

- **一级**，自上而下：配置读坏时的那一行说明（只在读坏时出现）→ 每台 Device 一行（名字；电量或
  短原因；按"菜单显示"的设置写来源与多久前、标出 Primary Device）→ "托盘上画哪一台"（自动（电量
  最低）/ 每台 Device）→ "图标样式 ›" → "菜单显示 ›" → "登记设备 ›" → "开机自启" → "打开配置文件"
  → "退出"。
- **"图标样式"与"菜单显示"按设计稿**：第二层右边写当前值；最里一层每个选项前挂一张按托盘真实尺寸
  画的预览位图；"恢复默认"只恢复图标样式那六项。
- **"登记设备 ›"**：
  - 未登记的蓝牙设备（本机扫到、带电量属性、地址不在任何 Device 里）：每一台 → "登记到 ›"（**只列
    还没有蓝牙地址的 Device**）/ "新建一台 Device"
  - 认得但没登记的 HID 设备（身份表认得、本机在场、配置里没有）：每一台 → "新建一台 Device"
  - "解除蓝牙登记 ›"：列出有蓝牙地址的 Device
  - 新建的 Device：名字取蓝牙名或身份表里的名字；id 由名字派生，撞了就加后缀；HID 设备照身份表写
    driver 与 Endpoint 块，蓝牙设备只写蓝牙块
- `show_unknown_ble` 去掉：未登记的蓝牙设备的去处就是"登记设备 ›"，一级的设备行不再列它们——同一台说在
  两处。用户 2026-09-15 审 `menu-as-designed` 设计稿时定（parking lot Q286）；配置项本身随票 14 删。

### Device 的 schema

- **`driver` 改成可选**：配了 Wired 或 Dongle24G 才必填，缺了照现在一样报配置错误。只走蓝牙的 Device
  不写它——写一个占位值等于在配置里说假话。

### 图标渲染（新）

- 纯函数：设置、图标状态、电量、尺寸、调色 → 位图。像素字形、每个画法在每个尺寸上的几何、调色板，
  一律照设计稿的渲染器（ADR-0005）。
- 尺寸 16 / 20 / 24 / 32；显示缩放落在别的档时取最近的那一档。调色跟随任务栏的深浅色。

### 词汇

- 代码与用户看得见的文字里的"这一趟"，按 `CONTEXT.md` 分成"一轮"与"一次取数"。

### 与 `screen-as-a-function` 的关系

- **票 01 与 03 由本 spec 取代**：命令行没了，`cli::status` 整个消失，搬家的目的地与那道缝都换成了

## Testing Decisions

好的测试只测外部行为，不测私有函数——这个仓库用集成测试，让编译器守着这一条（第 1 趟 `/settle` 的 Q3）。

**四道缝：两道现成、两道新开**（写 spec 时与用户确认过）。

- **一次取数**（现成）：不改行为。票 04、05 的用例照那两张票。
- **配置读写**（现成，扩展）：`pin_primary` 写 `"lowest"`；`[tray]` 回写；登记到已有 Device、新建
  Device（蓝牙 / HID）、解除登记；自动补空块；`driver` 可选；`low_battery` 的读取与单台覆盖。
  prior art 是现有配置用例那种逐行断言："只动了这一处，别的一个字节没变，注释一句不丢"。
- **托盘内核**（新）：用假时钟和罐装的一次取数结果驱动。每条至少一个用例：
  - 图标状态的优先顺序，特别是低电压过 Stale、充电中压过低电、暂停压过一切
  - 每台 Device 各走各的节奏，以及"还没读到过时按优先级最高的那条"
  - 任一台有新结果时开始新的一轮
  - 低电通知：每次跌破一次；读到充电中或回升后重新武装；拿上次已知值顶上的不触发；不是 Primary
    Device 的也提醒
  - 配置读坏时沿用上一份并给出告警
  - 本机设备变化触发自动补空块，并出通知
  - 菜单模型："登记设备"列谁不列谁、"登记到"只列没有蓝牙地址的 Device、配置读坏时顶上那一行
  - 悬停提示与菜单行的确切文字
  - 首次运行生成草稿并通知；第二个实例来敲门时弹通知
  
  prior art：Primary 选择与陈旧判定那几份用例里的假时钟；排版那批用例对确切字符串的断言——那批
  用例本身迁到这一层，断言对象从命令行那几行字换成菜单行与悬停提示。
- **图标渲染**（新）：基准来自设计稿的渲染器，导出成**文本网格**（一个像素一个字符，字符对应调色板
  里的一格），存进用例目录。覆盖面：缺省设置下 8 个图标状态 × 4 个尺寸 × 2 种调色；再对每一项设置，
  从缺省出发只改那一项、每个取值各一组。**不做全组合**（上万张，没有信息量）。设计稿要加一个
  "导出基准"的入口。
- **Win32 外壳不做自动测试**，靠一张手工验收清单：手动启动弹 UAC；勾上开机自启、重启后不弹 UAC 且
  图标出现；再启动一次弹"已经在托盘里了"；右键菜单、子菜单与预览位图；改设置立刻重画；深浅色切换
  与缩放变化时重画；插拔 dongle、插线充电时自动补配置并通知；低电通知；退出后不再轮询。
- gate 三条（`fmt --check`、`clippy --all-targets -D warnings`、`test`）全绿。

## Out of Scope

- **键盘 2.4G**：`docs/gaps.md` 与 `docs/protocol.md` 第 7 节记着，下一步是 USB 抓包。
- **查清为什么要提权**：程序清单一套上，它就不挡路了。
- 从托盘里删除 Device；在托盘里改 `[general]` 的其他设置（低电阈值、轮询间隔、暂停名单等）——改
  配置文件。
- 安装程序、代码签名（UAC 框会显示"未知发布者"）、自动更新。
- "进程名不写 `.exe` 就认不出来"那条缺口。
- `battery-readout` spec"明确不做"里的那些（自绘弹出面板、剩余时间估算、BLE GATT 主动读取……）照旧不做。
- `render` 那五个参数的 data clump 不单列：它随命令行排版一起退场，内核重新定形状时自然消失。

## Further Notes

**两条决定该各落一条 ADR**，都满足"改起来贵、不看上下文会奇怪、真权衡过"：

1. **成品不带命令行，诊断工具只留在示例程序里。** 备选"两个 exe"（命令行普通权限、托盘带清单）被否。
2. **程序清单 + 计划任务，而不是 Run 键或程序自己提权。** 备选"自己提权 + Run 键"能让开机也弹
   UAC、也不必让命令行跟着提权，被否；随后命令行整个取消，那条代价就消失了。

建议放进第一张票里一起写。

**`low_battery` 那件事值得记一句**：它和 `docs/gaps.md` 的"用户故事 17 是空的"同形——文档描述的是
设计，不是这个二进制今天做得到什么。这份 spec 把它变成真的。

**名字**：叫 `resident-tray`，取 README 第一句的"常驻"：它建的就是一个常驻的托盘。
