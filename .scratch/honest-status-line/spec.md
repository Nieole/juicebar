# 那一行只说它答得出的话

Status: ready-for-agent

用户看得见的措辞改动，两处。术语一律按 `CONTEXT.md`（Reading / Stale / Unknown / 失联 / 暂停 /
**读取异常** / 上次已知值）。相关决策见 `docs/adr/0002`（电量数值来源与不可信值）与
`docs/adr/0004`（坏帧时取有界的沉默）。

出处是第 1 趟 `/settle` 结算出来的 Q13 与 Q39 尾段，磨制过程见 `.scratch/homeless-1.md`。
**排在 `readout-and-config-modules` 之后**（两种 diff 不该互相污染），所以下文的接缝按那一趟
落地之后的位置来说；**但本 spec 不技术性依赖那一趟**，两处改动在今天的代码上一样做得到。

## Problem Statement

那一行会**断言它不知道的事**，两处。

**一、设备回了坏帧时，那一行说"都没读到"。** 今天整行读起来是：

> 读不到 —— 全部 Endpoint 都没读到 —— Wired: 读取异常：电压 2000 mV 不在 3050..=4350 mV

"都没读到"不准：**我们读到了，只是读到的东西不可信。** 而且**两个前缀说的是同一句话**，
一个在失败那个枚举的 `Display` 里、一个在失联原因那个函数里 —— 而两句都是那个不准的说法。
取数链路那张票的验收框要"校验不过时显示读取异常、不显示数字"；数字确实没显示，但**"读取异常"
只出现在最内层**，被外面两句话盖住了。

这两种说法要用户做的事**完全不同**：失联多半是没插、没开、接收器拔了；读取异常是固件或协议
对不上，或者厂商上位机在抢同一块共享缓冲区。混成一句，用户会去查一个不存在的连接问题。

**二、退到上次已知值的那一行照印"充电中"。** 电量与电压是**那一刻的测量值**，行尾一句
"已陈旧，上次已知值"就把它们限定完整了。而充电态是一个**现在时的状态断言**，而状态在设备失联
期间**恰恰最可能变了** —— 用户把它收进抽屉、或者刚给它插上线。

这一处特别值得改，是因为这个仓库**本来就有**处理它的规矩：说不上来的那一格整个不印（键盘的
充电态与键盘的电压都是这么处理的）。这不是缺一条新机制，是一条已有惯例还没应用到的地方。

## Solution

那一行只说它答得出的话。

1. **两个前缀合成一个**，措辞按失联原因那个函数**已有的三条分支**选：试过了都失败 → 一句中性的
   （不预判是没读到、还是读到了坏帧），后面每条 Endpoint 各自的原因紧跟其后；一条都不在场 /
   一条都没配 → "读不到"照旧准确，一个字不动。结果**比今天短**：一句换掉两个。
2. **退到上次已知值时，充电态那一格整个不印**；电量与电压照印，行尾那句标注照旧。

## User Stories

1. 作为用户，我想在设备回坏帧时那一行不说"都没读到"，这样我不会去查一个根本不存在的连接问题
2. 作为用户，我想那一行分得清"没插 / 没开"和"固件或协议对不上"，这样我知道该去插线，还是该去
   关掉厂商上位机
3. 作为用户，我想那一行不出现两句意思相同的话，这样我扫一眼看到的是原因，而不是重复的前缀
4. 作为用户，我想在全是超时的那一种里仍然看得到每一条 Endpoint 各自怎么失败的，这样换成中性的
   总结不等于信息变少
5. 作为用户，我想"一条 Endpoint 都不在场"仍然说"读不到"，这样最常见的那一种（设备没插、蓝牙
   没配对）措辞不变，我不必重新学一遍
6. 作为用户，我想那一行不比今天更长，这样一屏还是能看完全部 Device
7. 作为用户，我想在看到上次已知值时那一行**不**告诉我设备"充电中"，这样我不会以为它此刻插着线
8. 作为用户，我想在看到上次已知值时仍然看得到上次是多少电、多少电压，这样我知道它被收起来之前
   是什么状态
9. 作为用户，我想"说不上来的那一格整个不印"这条规矩在所有情形下一致，这样我看到一格有值，
   就知道那个值是真的
10. 作为用户，我想行尾"已陈旧，上次已知值"照旧在，这样我始终知道这个数不是现状
11. 作为用户，我想暂停那一行一个字都不变，这样这次改动只碰它该碰的那一维
12. 作为读代码的人，我想**读取异常**这个状态在词汇表里有定义，这样我不会拿失联或 Unknown 去指它
13. 作为下一个动那句失败措辞的人，我想它只有**一个**出处，这样我不必找齐两个前缀才改得动一句话
14. 作为下一个读失败那个枚举的人，我想它文档注释里"两句话各自完整、**不共用前缀**"那条约定在
    代码里真的成立，这样注释不再说假话
15. 作为审这次改动的人，我想它排在两次搬家之后，这样它的 diff 全是内容改动、一处移动都没有
16. 作为在并行 worktree 里做这两张票的 agent，我想它们碰的函数不相交，这样合并不会打架

## Implementation Decisions

### 失败那句话

- **整句话只有一个出处**：失联原因那个函数拥有它的全部，**包括开头那个标记**；失败那个枚举的
  `Display` 对失联那一支直接印它、不再自己加前缀。**这不是新约定** —— 那个 `Display` 的文档
  注释早就写着「两句话各自完整、**不共用前缀**」，今天那两个前缀本身才是违例。暂停那一支
  一个字不动。
- **标记按已有的三条分支选**：
  - **试过了、都失败** → 「**没有可信的读数**」。它对超时与读取异常**都**成立，而卖掉的那点
    精确度**后面每条 Endpoint 自己补上了**（"Wired: 超时"就在同一行紧跟其后）—— 那句总结本来
    没有加信息。
  - **一条都不在场** / **一条都没配** → 「**读不到**」，措辞一个字不改（它被打磨过两轮：话要
    说到"枚举不到它们"为止，把"设备没插"降格成一个问句，因为一句话要同时对三种 Endpoint 成立）。
- **不加取数失败的分类枚举**（`docs/adr/0004`）。外层措辞需要的那个区分，这三条分支已经**免费
  给了**；一个穿过每一个驱动错误路径的枚举在这里买不到别的东西，而靠字符串嗅探是明确否过的路。

### 充电态那一格

- **退到上次已知值时整格不印**，电量与电压**照印**。理由是这不是新机制，而是仓库已有惯例的应用：
  说不上来的那一格整个不印。电量与电压是那一刻的测量值、行尾标注已经限定完整；充电态是现在时的
  状态断言，而状态在失联期间最可能变了。
- **不改成过去时措辞**（"当时在充电"）。已有规矩：一个只为措辞存在的分支不值得 —— 而这里能省下
  的正是那个分支。
- 一行 Device 的排版那个函数**已经收着"这个数从哪儿来的"这一维**，所以充电态那一格改成同时看
  它就行，**不加参数**。
- 陈旧到不该再显示数字的那一档**不受影响**：它本来就把电量、充电态、电压整段换成一个日期。

### 票与边

- **两张票，碰的函数不相交，可并行**（失联原因与失败枚举的 `Display` ／ 一行的排版）。
- 两张都不与前一份 spec 的三张票撞：那三张全部落地之后本 spec 才开工。

## Testing Decisions

好的测试只测外部行为，不测私有函数 —— 这个仓库靠集成测试让编译器来守这一条。

**接缝全部是现成的，一条新的都不加。** 这一点在几张票之前还做不到，值得写明：那句失败措辞
原先只在 `run` 里拼出来、测不到，而厂商上位机那张票把它提成了失败枚举的 `Display`、
Primary 那张票又把**整行**提成了那几行的合成函数（`run` 现在只剩 `println!`）。

- **失败那句话**：经取数那一步返回失败、断言失败枚举的 `Display`。四种情形各一条 ——
  全是超时 / 混着读取异常 / 一条都不在场 / 一条都没配。prior art 是现有那条"不合理的帧读成
  读取异常而不是一个数字"的用例。
- **充电态那一格**：经一行 Device 的排版函数，两条 —— 上次已知值那一份不印充电态、
  当场读到的那一份照印。prior art 是现有那批对排版结果断言**确切字符串**的用例（键盘那两格
  不印就是这么守住的）。
- **整行**：经那几行的合成函数至少一条端到端断言，确认这两处改动拼起来读得通。
- **现有用例里断言过"读不到 —— 全部 Endpoint 都没读到"那句原话的，必须跟着改断言。**
  这一条要写明白，因为它与前一份 spec 的判据**正好相反**：那一趟"改断言 = 搬家夹带了行为"，
  这一趟**"改断言 = 做对了"**。
- gate 三条（`fmt --check`、`clippy --all-targets -D warnings`、`test`）全绿。

## Out of Scope

### 暂停那一支尾句里同一个措辞，这一趟不动

写这份 spec 时核过了：暂停时那一行末尾会说「；剩下的也没读到 —— {原因}」，句式与失联那句同源。
**那条尾句今天不说假话**，因为三件事凑在一起：上位机只跟两条 HID 抢，所以暂停时**在场的 HID
一条不剩地都让开了**，那份原因里只可能有 `Ble`；而合理性校验只在两个 HID 驱动里跑，**`Ble` 压根
产生不了读取异常**。它会**开始**说假话的条件是三件之一：加进第四种 Endpoint；出现一个只跟其中
一条 HID 抢的上位机；或者给 `Ble` 也加上合理性校验。

**但本段原先由此断言"暂停那一支今天不说假话"，那是过度概括，已由票 01 的 Q89 推翻。**同一个变体里
**另一句**今天就是假的：原因列表为空时那一行接的是「关掉它就会恢复」，而**列表为空只说明这一趟
什么都没试过**，不说明试了就会答话。接收器插着、设备关着的那一趟正是这样——接收器有自己独立的
一组 VID/PID（`CONTEXT.md` 的 Dongle24G 那一条），所以它照样在场、照样被让开、原因列表照样是空的,
于是程序许下一个关掉上位机也兑现不了的承诺。那恰好是当初引入这份原因列表要拦的那一类假承诺。

**这一处仍然不在本 spec 范围内**（它要的是一个比"列表空不空"更强的判据，那是另一件事），
但范围外的理由是"另一张票的活"，**不再是"它今天不说假话"**。详见 Q89。

## Further Notes

**词汇表已经先行。** **读取异常** 这一条在磨这份 spec 的过程中一落定就写进了 `CONTEXT.md`，
_Avoid_ 同时点名失联（那是去问了、问不到，而这里设备答了话）与 Unknown（那是帧本身是好的、
只有电量那一个字段不可采信）—— 那两条原来只互相点名，**漏了这第三样**。本 spec 的措辞一律按它。

**Q13 当年记的那个障碍已经不存在了。** 它写着「最终印在屏幕上那一行是 `run()` 拼的，而 `run()`
要真去枚举本机 HID 通路，测不到」，所以它把自己推给了"票 06 或收口那批"。后来两张票分两次把它
提了出来 —— 这是一条记录**因为别的票顺手改善了地形而变便宜**的例子，也是把它推迟掉是对的证据。

**名字**：叫 `honest-status-line`，因为两条改动的共同点就是"那一行不许断言它不知道的事"，
`honest` 是那个共同点本身，而不是一个抽屉的名字。
