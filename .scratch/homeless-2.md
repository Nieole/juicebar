# 第 2 趟 `/settle` 结算出来的 4 条无主的活

**Status:** 交接文件 —— 给 `/grill-with-docs` 用，磨完就可以删
**Opened:** 2026-09-10
**出处:** `.scratch/parking-lot.md` 第 2 趟结算索引（范围 Q58 – Q99）；这 4 条的正文在 git 的 `67b645a` 里

## 读这份东西的人要先知道两件事

**一、这一堆做过的思考比一般的想法更少。** `/settle` 的分道**只贴标签、不做决定**，所以这里
每一条都还是一袋观察，不是一条磨过的线。**预期它在 grill 里缩水**——想清楚了可能其实是记录，
或者是上游已经答过的问题。

**二、它们的共同点：`readout` 那一层的话已经改准了，但托着这句话的名字与结构没跟上。**
上一趟队列买的是"那一行说的是不是实话"，两张票都交付了；剩下这四条全长在同一层的**背面**——
一个仍在许空头承诺的分支、一个词汇表明令不许这么用的类型名、一半没有接缝所以 `pub` 仍是"为了
测试"的呈现代码，外加一处用户看得见的字符串里的洞。**三条在 `src/readout.rs` 与 `src/cli/status.rs`
之间，一条在 `src/cli/probe.rs`。**

**出来的努力要有自己的名字**——它建的是什么，不是它从哪个抽屉来的。

## 那一层的话与它的名字对不上

### Q89 —— 「关掉它就会恢复」对一台关了机的设备是假话，而这一支今天就在说

**已核实仍然如此**：`src/readout.rs:210`，`failures.is_empty()` 为真时那一行末尾写「，关掉它
就会恢复」。

接收器插着、设备本体关了机的那一趟：`Dongle24G` 照样被枚举成"在场"（`docs/adr/0001`：接收器
有自己一组 VID/PID），`pauses(Dongle24G)` 为真，于是它让开、`failures` 全空、走的正是这一支。
关掉上位机之后那条通路照旧超时——因为设备是关着的。

**它与上一趟要治的病同形**：那一行断言了一件它不知道的事。上一趟只核过这一支的**尾句**
（「；剩下的也没读到 —— {原因}」，那一句有三条事实撑着）；`failures` 全空那半句从没被核过。
spec 的 Out of Scope 已按它改成实话（`3328771`），**但代码这一半没动**——票 01 的票面写着
`Paused` 一个字都不改。

**形状**：一处 `Display` 分支的措辞，把那句关于未来的承诺降格成条件句。够不上一张自己的票，
但要有人接。

### Q91 —— 读取异常从一个叫 `Lost`／失联的变体里出来，而 `CONTEXT.md` 明令不许这么指

用户看见的那一行已经不说"都没读到"了，但**代码里那个状态照旧叫 `Lost`**。`CONTEXT.md:55`
「读取异常」那一条写着 _Avoid_：「拿失联说它——那是去问了、问不到，而这里设备答了话」。
下一个读这段代码的人，仍然会在一个叫"失联"的变体里撞见读取异常。

**已核实的范围**（比看着便宜）：`Lost` 只出现在 `src/readout.rs` 一个文件里——代码三处
（构造 `:105`、`paused_by()` `:175`、`Display` `:194`）加变体定义 `:148` 与文档 `:189`，别的
模块一次都没提它。

**另外三处"一条都没读到 = 失联"的定义在别处**：`src/primary.rs:60`、`src/cli/status.rs:163`、
以及 `CONTEXT.md:64`「失联」词条本身。

**两条路都站得住**：改名让类型跟着措辞走；或者在 `CONTEXT.md`「失联」那一条里**承认这个变体
比词条宽**（`docs/agents/domain.md` 要的是把冲突摆出来，而不是默默推翻它）。选哪条是这堆东西
在 grill 里该定的第一件事。

### Q69 —— 呈现那一半没有接缝，所以它的 `pub` 仍然是"为了测试"

`readout` 那一半搬完了，`read` 的 `pub` 现在是"它是这个模块的接口"。**另一半没有**：
`render` / `primary_lines` / `unregistered_ble_lines` / `DeviceRow` 在 `src/` 里**一个非测试
调用方都没有**，`main.rs` 只调 `run`。它们 `pub` 的唯一理由就是 `run` 测不到（它要真去枚举
本机 HID）。

**这不是位置问题，搬到哪儿都一样**——只要 `run` 还是那道躲不开真系统的墙。真正的归宿是**给
呈现那一半也划一道缝**，那时 `render` 的 `pub` 自然变成那道缝的接口。上一趟明确把它放在
Out of Scope（"不再往下拆 `cli::status` 剩下的那约 440 行"）。

**同一处还挂着一笔 data clump，而且长大了**（这条从第 1 趟的 `homeless-1.md` 带过来，那份
文件已经磨完删掉）：`render` 上一趟是四个参数，本趟加了 `provenance` 之后**是五个**
（`src/cli/status.rs:297`：`sourced` / `level_source` / `staleness` / `provenance` / `paused_by`）。
把 `(reading, staleness, provenance)` 捆成一个类型站得住，但正确形状取决于托盘那一步要什么。

## 一处路过的洞

### Q88 —— `probe` 那句话里有 13 个字面空格，印给了用户

`src/cli/probe.rs:78`：那句 `bail!` 的格式串是「先跑 `juicebar scan` 看看有哪些，⟨13 个空格⟩
注意 out（或 feat）列为 0 的通道发不了命令。」——一处续行的 `\` 丢了，那 13 个空格进了**用户
可见**的那句话。它不是任何一张近期的票造的。

**处置早就定了**（`docs/agents/queue-conventions.md` 第 2 条就是从它和 Q79 定出来的）：**修掉，
但它够不上一张自己的票**——下一个动 `src/cli/` 的人顺手收掉即可。代价是一个字符，而且没有任何
用例断言这个字符串。

**它留下的那条验收 grep 已经被污染了，得收窄**：原话是「`grep -rnE '\S {5,}\S' --include=*.rs
src tests` 实测只有这一处」。**今天再跑，多出 9 条命中，全是 `src/cli/status.rs:313–321` 那段
对齐缩进的注释**（上一趟新写的）。排掉注释行之后仍然**只有 `probe.rs:78` 这一处**：

```
grep -rnE '\S {5,}\S' --include=*.rs src tests | grep -vE '^\S+:[0-9]+: *//'
```

这一类**总共两处、还剩这一处**（另一处是 Q79，已修）。

**它连着一条规矩，而那条规矩现在就在这堆里**：Q90（第 2 趟的岔路，已决"那一行维持不折"）
问的是"用户可见的长字符串到底怎么写"——一律 `concat!` 分段，还是一律不折并明写"字符串不受
列宽约束"。这两条是同一类的两面：Q88 是现行写法的伤口，Q90 是那条规矩本身。**决策者把规矩
这一半交到这里定**，理由是一处一处地折只会让下一个人再猜一遍。

定它时手上有的实测：`src/readout.rs:353` 是 129 列，`src/cli/probe.rs:78` 是 140 列（**别拿它
当先例，它 140 列正是因为 `\` 丢了**）；`rustfmt` 不折字符串，所以 `fmt --check` 对两者都没有
意见；`concat!` 全仓库两处（`tests/config.rs:105 / 814`），都是 `env!` 拼路径，**没有一处是拿它
折散文**——所以真要权衡的是"要不要为一句话引入一条新惯例"。定下来之后该写进
`docs/agents/queue-conventions.md`，和另外两条并列。
