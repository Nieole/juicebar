# 01: 配置模块拆成四个文件，公开面一个字不变

**What to build:** 加一台设备、改一句草稿文案、改回写机制——这三件不相干的事从此**各改一个
文件**。而对外这次搬家**不可见**：公开路径一个字不变，调用点和现有配置用例零改动。

**Blocked by:** None (can start immediately) —— 与票 02 碰的文件不相交，两张可并行。

**Status:** ready-for-agent

- [ ] 配置从单个文件变成一个模块目录，四个文件各只有一个改动理由：**模块入口**（schema、解析、
      re-export）／**身份表**（那张写死的实测表，与"这台设备对上表里哪一条"的判定）／
      **草稿**（生成，与那批用户可见的文案常量）／**编辑**（格式保留的补全与 `primary` 回写）。
      叶子辅助函数跟着它们的调用方走
- [ ] 用 `mod.rs` 而不是同名文件加目录，与仓库现有的两个模块目录一致
- [ ] 模块入口**原样 re-export 全部公开面**，所有调用点一行都不改
- [ ] 现有配置用例文件**一行都不改**，且不改语义地全绿 —— 这是"没夹带行为变化"最硬的证据
- [ ] 那个用例文件开头「四样东西住在同一个模块，所以用例也在同一个文件里」的说明改成实话
      （新理由：公开面仍然是一处）。**不分那个用例文件**
- [ ] 一处行为都没变：草稿生成的文本、`config-refresh` 补全的结果、`primary` 回写的结果，
      逐字与搬家前相同
- [ ] gate 三条（`fmt --check`、`clippy --all-targets -D warnings`、`test`）全绿
