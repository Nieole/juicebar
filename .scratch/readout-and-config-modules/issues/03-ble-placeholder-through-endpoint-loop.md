# 03: 草稿里的 Ble 占位改由 Endpoint 那个穷举循环产出

**What to build:** 将来给 Endpoint 加第四种时，**编译器在草稿生成这一处也把人指过去**。草稿里
三条 Endpoint 的占位从此出自同一套逻辑；蓝牙那一条即使补不上，也说清**为什么**补不上、
以及该去哪儿抄。

**Blocked by:** 01（配置模块拆成四个文件）—— 它的落点在草稿那个文件里。这条边是有意的：
本票要往循环里接一条说明，那是**内容改动**，落在搬家之后，票 01 的 diff 就仍然是纯移动、
本票的仍然是纯内容。

**Status:** resolved

- [x] 硬写的蓝牙占位常量退掉，`Ble` 走那个按优先级穷举的循环，连同已有的"注释掉的占位"渲染
      一起产出
- [x] 加一种 Endpoint 时，**草稿生成这一处会编译失败而不是静默少说一条** —— 这是本票买到的东西
- [x] "为什么补不上"由一条 per-kind 的说明给出，调子照 `config-refresh` 已有的那条分支：
      BLE 射频是另一颗芯片，与 dongle 之间没有能缝合的字段，所以猜不出来，
      去 `juicebar scan` 那一段抄
- [x] 一条新用例断言草稿里三条 Endpoint 的占位出自同一套逻辑（蓝牙那一段带着注释掉的占位该有的
      形状，并且说清为什么补不上）。prior art 是现有那批对草稿文本断言的用例
- [x] **不给草稿加 BLE 扫描**：身份表里没有 BLE 身份，扫出来的地址无法归属到某一台 Device，
      而那正是 `juicebar scan` 已经在印的东西
- [x] 生成的草稿对用户仍然可读：三条 Endpoint 的措辞与排布一致，而不是两条生成、一条手写
- [x] **顺带把 `NOTHING_RECOGNISED` 里那个过期的路径改对**：那句用户可见的话告诉用户"表在
      `src/config.rs`"，而票 01 把那个文件拆掉了。票 01 **故意没改它** —— 它整张票的证据价值
      全靠"草稿文本逐字不变"这一条，拿它去换一个随处可做的路径修正是笔坏账。本票本来就在动
      草稿生成，所以这一格零成本地归你。出处是 parking lot **Q58**
- [x] gate 三条（`fmt --check`、`clippy --all-targets -D warnings`、`test`）全绿
