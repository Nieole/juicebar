# 02: 取数搬进自己的模块，`pub` 不再是"为了测试"

**What to build:** 「这一趟拿得出什么读数」成为一个**有名字的模块**——从"谁在场"到"这一行的
原料"是一个完整的故事。搬完之后 `read` 的 `pub` 是因为它**是这个模块的接口**，而不是为了让
集成测试驱动得到；而 `cli::status` 只剩"印出这几行"这一个改动理由。

**Blocked by:** None (can start immediately) —— 与票 01 碰的文件不相交，两张可并行。

**Status:** resolved

- [x] 新模块住在 crate 根，与 endpoints / staleness / clock / state / primary 同级
      （**它不是 CLI 的一部分** —— `status` 只是今天唯一的调用方，常驻轮询那一步会是第二个）
- [x] 它收下：按优先级取一次数、驱动分发、"这一趟让开了哪几条"的判定、失败那个两变体枚举
      （**失联** / **暂停**）连同它的 `Display`、"取不到就退到上次已知值"那个接缝、以及它交出来
      的那个原料结构。**故事的终点是"这一行的原料"** —— 再往后是排版，不进来
- [x] 那句失联原因的拼装一起搬进去，并**留在私有**：它经失败枚举的 `Display` 就观察得到，
      不必多开一个 pub
- [x] **不 re-export。** 旧路径搬家之后会指向一个不该拥有取数的模块，那是一句假话；
      全部调用点与用例前缀改成新模块名
- [x] `cli::status` 留下：`run` 的接线、一行 Device 的排版（含陈旧标注、暂停标注、来源那一段）、
      那几行的合成（Primary 标注与未登记的 BLE 设备）。**这一趟不再往下拆它**
- [x] 原来那个测试文件沿**同一条缝**分成两个：取数那一半进新的用例文件，排版与那几行的合成
      留在原处；共用夹具留在共用模块里，两边都用得到
- [x] **分文件与改前缀时一条断言都不改**，全绿 —— 任何需要改断言的地方都是"搬家夹带了行为"的信号
- [x] 搬完之后新用例文件的自我说明与它测的东西对得上（原来那个文件承认自己测的是 Endpoint 合成，
      而那不是 `cli::status` 该管的事）
- [x] gate 三条（`fmt --check`、`clippy --all-targets -D warnings`、`test`）全绿
