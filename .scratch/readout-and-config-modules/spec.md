# 取数与配置各归其模块

Status: resolved

**零行为变化。** 这份 spec 交付的全部是边界：两个长成多用途的文件各自搬进自己的模块，
外加一处让编译器守住的完备性。术语一律按 `CONTEXT.md`（Device / Endpoint / Reading /
Stale / Unknown / 失联 / 暂停 / 读取异常）。相关决策见 `docs/adr/0003`（回写 config.toml）
与 `docs/adr/0004`（坏帧时取有界的沉默）。

出处是第 1 趟 `/settle` 结算出来的 Q4 / Q5 / Q47 / Q50 / Q57，磨制过程见
`.scratch/homeless-1.md`。**先做这一份，再做 `honest-status-line`** ——两种 diff 不该互相污染。

## Problem Statement

两个文件长成了多用途的东西，而每一个用途都有自己的改动理由：

- **`src/cli/status.rs`（743 行）**装着四样：`run` 的接线、取数策略（按优先级依次试、降级、
  失联与暂停的判定、退到上次已知值）、那几行的合成（Primary 标注、未登记的 BLE 设备）、
  以及一行 Device 的排版。
- **`src/config.rs`（1096 行）**装着四样：配置 schema 与解析、写死的实测身份表、
  约 200 行用户可见的草稿文案、以及 `toml_edit` 那套原地编辑机制。加一台设备、改一句提示、
  改写入机制，三件不相干的事改同一个文件。

**它们不是疏忽长成这样的**，每一处当时都有站得住的理由：想搬它的那张票，和正在改它的那张票
是并行的。parking lot 里有四条记录明写着"等票 XX"。**并行结束了，而没有人回来接。**

症状已经浮出来两处：

1. `tests/status.rs` 第一行的自我说明是「`cli::status` 的外部行为，**也就是 Endpoint 合成**」
   ——测试文件自己承认它测的不是 `cli::status` 该管的事。
2. `read` 与 `render` 的 `pub` 是**"为了测试"**才放开的，而不是因为它们是某个模块的接口。
   下一个人完全可能把它们当成随手可以收回的实现细节。

还有一处独立的完备性缺口：草稿里那段注释掉的 `[device.bluetooth]` 占位是个**硬写的常量**
（`BLE_PLACEHOLDER`），不经过 `EndpointKind::PRIORITY` 那个循环。于是将来加第四种 Endpoint 时，
**编译器不会把人指到草稿生成这一处**——而这个仓库通篇靠的正是"留着穷举 `match`，让编译器当
守门人"（Q57 记的那次合并，五处冲突六个编译错误全被工具抓住，正是因为票 10 留了穷举）。

## Solution

三件事，加起来是零行为变化：

1. **取数搬进自己的模块**：`status` 那一趟"拿得出什么读数"是一个完整的故事，从"谁在场"到
   "这一行的原料"，它该有一个自己的名字。搬完之后 `pub` 不再是为了测试——它本来就是这个模块
   的接口，而 `cli::status` 只剩"印出这几行"这一个改动理由。
2. **配置拆成一个模块目录**：schema、身份表、草稿文案、写入机制各一个文件。**公开路径一个字
   不变**（`mod.rs` 原样 re-export），所以调用点与现有配置用例零改动——这次搬家对外不可见。
3. **草稿里的蓝牙占位退掉常量**，改由那个 `PRIORITY` 循环连同"为什么补不上"的说明一起产出。
   买到的是编译器在草稿这一处也守着"加一种 Endpoint 时别漏了它"。

## User Stories

1. 作为下一个动取数逻辑的 agent，我想让"这一趟拿得出什么读数"住在一个模块里，这样我不必先读完
   743 行才弄清排版和取数在哪儿分家
2. 作为下一个动取数逻辑的 agent，我想让 `read` 的 `pub` 是因为它是那个模块的接口、而不是"为了
   测试"，这样我不会误以为它是个可以随手收回的实现细节
3. 作为读测试的人，我想测 Endpoint 合成的用例住在一个名字对得上的文件里，这样文件名不再和它
   第一行的自我说明打架
4. 作为下一个读 `cli::status` 的人，我想它剩下的内容只有"印出这几行"这一个改动理由，这样我
   为了改一句措辞不必绕过取数策略
5. 作为要加一台设备的人，我想只改身份表那一个文件，这样我的 diff 不和草稿文案、写入机制混在一起
6. 作为要改草稿文案的人，我想那约 200 行用户可见的字符串住在自己的文件里，这样改一句提示不必在
   schema 和 `toml_edit` 之间翻页
7. 作为要改回写机制的人，我想格式保留那套住在自己的文件里，这样它那几个坑（表的位置继承、
   缺席时建表要钉位置）集中在一处
8. 作为调用配置模块的人，我想公开路径一个字都不变，这样这次搬家不需要我改任何东西
9. 作为跑现有配置用例的人，我想它们不改语义就照旧全绿，这样我能确信这次搬家没有夹带行为变化
10. 作为将来要加第四种 Endpoint 的人，我想编译器在**草稿生成**这一处也把我指过去，这样我不会
    漏掉"草稿里少说了一条 Endpoint"
11. 作为首次运行的用户，我想草稿里三条 Endpoint 的占位出自同一套生成逻辑，这样它们的措辞与排布
    是一致的，而不是两条生成、一条手写
12. 作为首次运行的用户，我想蓝牙那一条即使补不上也说清**为什么**补不上、以及该去哪儿抄，
    这样我不会在不知情的情况下缺一整条 Endpoint
13. 作为审这次改动的人，我想搬家的 diff 全是整块移动、内容改动一个字都没有，这样我 review 一遍
    就能确信它是安全的
14. 作为审这次改动的人，我想措辞与行为的改动排在后面、成为另一个努力，这样两种 diff 不互相污染
15. 作为在并行 worktree 里做这几张票的 agent，我想它们碰的文件不相交，这样合并不会打架
16. 作为将来给 `EndpointKind` 加变体的人，我想每一处穷举 `match` 都还是穷举的，这样编译器继续
    是那道守门
17. 作为读 `tests/config.rs` 的人，我想它开头那句"四样东西住在同一个模块所以用例也在一个文件里"
    在这次搬家之后仍然是实话，这样注释不会开始说谎

## Implementation Decisions

### 取数模块

- **新模块住在 crate 根**，与 `endpoints` / `staleness` / `clock` / `state` / `primary` 同级。
  它不是 CLI 的一部分——`status` 只是今天唯一的调用方，常驻轮询那一步会是第二个。
- **它收下这些**：按优先级取一次数的那个函数、驱动分发、"这一趟让开了哪几条"的判定、
  失败那个两变体枚举（失联 / 暂停）连同它的 `Display`、"取不到就退到上次已知值"那个接缝、
  以及它交出来的那个原料结构。**故事的终点是"这一行的原料"**——再往后是排版，不属于这里。
- **`lost_reason` 一起进去**，并且**留在私有**：那句话经失败枚举的 `Display` 就观察得到，
  不必多开一个 pub。
- **不 re-export**。`cli::status::read` 在搬家之后是一句假话——cli 不该拥有取数。测试里那 34 处
  前缀跟着改成新模块名，一次机械替换。（这与配置那一半故意不对称，理由见下。）
- **`cli::status` 留下**：`run` 的接线、一行 Device 的排版（含陈旧标注、暂停标注、来源那一段）、
  那几行的合成（Primary 标注与未登记的 BLE 设备）。约 440 行，**这一趟不再往下拆**。
- **与 `battery-readout/spec.md` 的「模块划分」相抵触，这里明写出来**：那份 spec 预言 Endpoint
  合成归 `endpoints` 模块。这里不那么做，两条理由——`endpoints` 的模块文档头第一句就是「接缝
  只回答**在场**，不回答**先试谁**」，把"先试谁"搬进去正好抵掉那句话；而那份 spec 预言的
  「Device 模型 + Endpoint 合成 + 陈旧判定集中一处」**从未成真**（陈旧判定去了自己的模块、
  Clock 去了自己的模块、Device 模型在配置模块里），所以那个分组今天没有依据。

### 配置模块

- **`config.rs` 变成一个模块目录，四个文件**：模块入口（schema、解析、以及 re-export）、
  身份表（那张写死的实测表与"这台设备对上表里哪一条"的判定）、草稿（生成与那批文案常量）、
  编辑（格式保留的补全与 `primary` 回写）。叶子辅助函数**只有一个调用方时**跟着它走；**调用方跨文件的按主题归组**——一个两侧都被借用的
  纯渲染函数，跟谁走都会让那个文件多一个改动理由，而"改一句草稿文案只动一个文件"对它本来就
  不成立（票 01 的 Q59 量到了这一处：`endpoint_block` 的共享是一条被文档明写的不变式——草稿
  写下的块与 `config-refresh` 补出来的块要逐字一致——不是耦合失误）。
- **用 `mod.rs` 而不是 `config.rs` + 同名目录**，与 `src/cli/`、`src/sources/` 一致。
- **模块入口原样 re-export 全部公开面**，于是调用点与现有配置用例**零改动**。这一处与取数那一半
  的不对称是有意的：配置模块的公开面本来就是这个模块的 API，四个文件是它的**内部安排**；而取数
  搬走之后，旧路径会指向一个不该拥有它的模块。
- **`tests/config.rs` 这一趟不分文件**，但它开头那句"四样东西住在同一个模块，所以用例也在同一个
  文件里"要改成实话（新的理由是：公开面仍然是一处，所以用例仍然在一处）。

### 草稿里的蓝牙占位

- **退掉那个硬写常量**，`Ble` 走 `PRIORITY` 循环连同已有的"注释掉的占位"渲染函数一起产出。
- **"为什么补不上"由一条 per-kind 的说明给出**，调子照 `config-refresh` 已有的那条分支
  （Q57 加的）：BLE 射频是另一颗芯片，与 dongle 之间没有能缝合的字段，所以猜不出来，
  去 `juicebar scan` 那一段抄。
- **不给草稿加 BLE 扫描**：身份表里**没有** BLE 身份（`identity()` 对 `Ble` 返回 `None`，
  正是因为没有能缝合的字段），所以扫出来的地址**无法归属到某一台 Device**，只能整份列出来
  ——而那正是 `juicebar scan` 已经在印的东西。往每份草稿里塞一份无法归属的地址清单是噪声。

### 票的切法与边

- **三张票**：取数搬家 ∥ 配置拆分（**两张不相交，可并行**），草稿占位 **blocked by** 配置拆分
  （它的落点在草稿那个文件里）。
- **不是宽重构，不走 expand–contract**：配置那一半靠 re-export 让调用点零破损，取数那一半的
  破损面是一次机械替换的 34 处。**两张都能单独落绿。**

## Testing Decisions

好的测试只测外部行为，不测私有函数——这个仓库靠集成测试让编译器来守这一条（私有的东西在
`tests/` 里根本看不见）。

**这一份 spec 的验收判据特殊：零行为变化，所以"现有用例不改语义地全绿"本身就是验收。**
任何一处需要改断言的地方都是一个信号——那说明搬家夹带了行为。

- **接缝全部是现成的，一条新的都不加。**取数那一侧是按优先级取数、退到上次已知值、以及失败枚举
  的 `Display`；呈现那一侧是一行 Device 的排版与那几行的合成（**整行**是可观察的，`run` 现在
  只剩 `println!`）；配置那一侧是草稿生成、补全、回写。
- **`tests/status.rs`（1495 行）沿同一条缝分成两个文件**，判据是**看一条用例断言什么，不看它
  调用什么**：断言排好版的那一行的留在原处，只断言取数交出来的东西（`EndpointReading` /
  `NoReading` / `RowReading`、假枚举的往返记录）的搬走。排版那半边照旧调取数去拿一份真读数
  ——那不是越界，是不手搓读数。
  **不要按"多少处调用"来分**：票 02 实测那 26 处 `read` 调用里有 9 处长在排版用例里
  （`read_or_last_known` 那 8 处里有 3 处），所以"26 处全搬"与"排版留在原处"**不能同时成立**
  （parking lot Q68，与 Q59 同一形状：票面两条规则在某个具体对象上互斥）。
  共用夹具**只把两边都真需要的**提进 `tests/common/`——它被编进每一个测试二进制，
  提多了会在毫不相干的目标上撞 `dead_code`。**分文件时一条断言都不改。**
- **`tests/config.rs`（1218 行）一行都不改**——那正是 re-export 的全部意义，也是这张票"没夹带
  行为变化"最硬的证据。
- **草稿占位那张票要一条新用例**：断言草稿里三条 Endpoint 的占位出自同一套生成逻辑（蓝牙那一段
  带着注释掉的占位该有的形状，并且说清为什么补不上）。prior art 是现有那批对草稿文本断言的用例，
  尤其是"补上的块落在正确的 `[[device]]` 底下"那一条。
- **gate 三条（`fmt --check`、`clippy --all-targets -D warnings`、`test`）在每一张票上都必须绿。**
  base 上 gate 本来就红的情形按 `docs/agents/queue-conventions.md` 处理。

## Out of Scope

- **任何行为变化。**措辞、失败分类、退到历史值时那一格充电态——全部归 `honest-status-line`
  那个努力，而它排在这一份之后。
- **不加取数失败的分类枚举**（`docs/adr/0004`：取有界的沉默）。
- **不再往下拆 `cli::status` 剩下的那约 440 行。**
- **不动"认设备靠写死的身份表"这个决定**（启发式那条路会写下错配置，理由已定）。
- **不给草稿加 BLE 扫描。**
- **`config-refresh` 仍然不新增 `[[device]]`、也不清理它自己留下的占位注释**（两条都是有意的，
  见 `docs/gaps.md`）。
- **不分 `tests/config.rs`。**
- 托盘图标与常驻轮询（本仓库 spec 的第 7、8 步，一直在 Out of Scope 里）。

## Further Notes

**这一批为什么会积到现在**，值得记一笔：两处当时不搬的理由都是"并行会撞车"，而 parking lot 里
四条记录明写着"等票 XX"——那几张票都落地了，**没有一张回来接**。一条"等票 XX"的记录需要有人在
那张票落地的那一刻把它捡起来，而这个仓库没有那个机制。这正是 `/settle` 存在的理由，也是
第 1 趟结算量到"每票 4.8 条记录"的一部分成因。

**`tests/config.rs` 分不分，是一个真的后续候选。**它 1218 行，而它开头给出的"用例在一个文件里"
的理由是「四样东西住在同一个模块」——这次搬家之后那个理由就换了（公开面仍是一处）。要不要沿着
四个文件把它也分成四份，值得单独想一次；这一趟没做，是因为它不在确认过的范围里，而且它会把
"零行为变化"这个干净的验收判据搅浑（分一个 1218 行的测试文件很难证明一条断言都没动）。

**名字**：叫 `readout-and-config-modules` 而不是 `parking-lot-cleanup`，是为了让它按价值和别的
活竞争。一个叫"清 parking lot"的努力读起来像必须先还的债，而这几张票该和其余的活站在同一条
起跑线上。
