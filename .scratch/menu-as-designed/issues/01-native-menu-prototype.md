# 01: 原型：普通菜单项在实机上画得出什么

**What to build:** 改设计稿之前，先把普通原生菜单项（ADR-0006）在这台机器上真的建出来看一眼。调研
`docs/research/native-menu-research.md` 里有几条只是推断，而改设计稿恰好要靠它们。写一个用完就扔的
Win32 小程序，用普通菜单项建出 spec 里那几份菜单的新形状，浅色、强制深色各弹一次，截图，把答案补进
调研文件。设计稿（票 06）按这里的实机结果画。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 小程序只用普通菜单项（不 owner-draw），建出这几份：
      - 一级：一行告警、两行设备行（一台正常，一台变灰）、"托盘上画哪一台 ›"（带右列）、"图标样式 ›"、
        分隔线、"退出"
      - "托盘上画哪一台"子菜单（单选）
      - "图标样式"第二层（右列写当前值）
      - "画法"与"灰状态"两个最里层（圆点 + 预览位图 + 文字 + 右列"默认"）
- [ ] 预览位图用现有的渲染器按 16 与 32 像素画出来，转成预乘过的 BGRA 挂上去；"灰状态"那一组是三张
      并排的宽位图
- [ ] 回答下面这几条，每条写明结论（是 / 否 / 是什么样子）并附截图：
      - 右列用制表符那一列，还是贴右对齐的那个字符，哪一种贴近设计稿
      - 带子菜单的项，右列显不显示、挨不挨着 ›
      - 不设"勾与位图共用一格"那个菜单样式时，圆点与预览位图是否并排
      - 32 像素的预览、三张并排的宽预览，把项与整列文字撑成什么样
      - 变灰的项悬停时是什么样子
      - 强制深色下，预乘位图的半透明边缘是否照常
      - 强制深色 / 强制浅色再刷新菜单主题，是否下一次弹出就生效
      - "深色任务栏、浅色应用"时，强制深色压不压得住
- [ ] "深色任务栏、浅色应用"那一条要切系统的深浅设置：请用户手动切一次，看完再切回去，不要由程序去改
      注册表
- [ ] 结论补进调研文件：把"查不实的"一节里被这次验证掉的条目改成查实的结论，注明"实机"，并写上是哪一版
      Windows、哪一档缩放；截图放在调研文件旁边
- [ ] 代码留在一个 `prototype/native-menu` 分支上，不进 master；调研文件与截图进 master
