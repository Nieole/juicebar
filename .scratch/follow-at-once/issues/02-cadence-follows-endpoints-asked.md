# 02: 节奏按真被问到的那几条走，每一格按此刻的配置算

**What to build:** 接收器插着、2.4G 不答、Ble 从缓存答话时，2.4G 仍然一分钟最多被问一次——而不是跟着 Ble 的
10 秒每次都先问一遍、在唯一的取数线程上等满 3 秒。改了配置里的轮询间隔，下一格就按新的算，不必等上一个
旧间隔跑完。（spec「节奏按真被问到的那几条」；接管 `resident-tray` 票 15 与 parking lot Q172。）

- **一次取数交回这一次问过哪几条 Endpoint**（`tried`）：按优先级真去试了的那几条，包括答了话的那条；让开的不算
  （压根没问）；一条都不在场、本机枚举不了时是空的。它随取数的结果（`Outcome`）一路交到内核（`Fetched`）。
- **节奏那一格每台记的不再是"下一次的时刻"**，而是上一次取数的时刻 + 那一次问了哪几条；时钟每走一格，按内核
  **此刻**手上的配置算间隔——`tried` 里各条间隔取最长的那个——到没到点。
- `tried` 为空沿用今天的兜底：按配置里优先级最高的那条；一条都没配的按三个间隔里最长的（Q170）。
- 陈旧判定不动：HID 那两条仍按各自读数来自的那条 Endpoint 间隔的 3 倍。
- 节奏那一格与取数那一层的模块文档随之改口（今天写着"按手上那份读数来自的那条"与"它按的是哪条读到了"那两段）。

**Blocked by:** None —— can start immediately

**Status:** ready-for-agent

      一条都不在场 → 空；Wired 在场读坏、24G 答话 → `[Wired, Dongle24G]`

      HUB 关了、下一次问到 24G 回到 `poll_interval_24g`；Wired 读坏落到 24G 按 `poll_interval_24g`
