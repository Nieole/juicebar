# 04: 换了 Endpoint 集合的那台当场再问

**What to build:** 菜单里把蓝牙地址登记到一台 Device、解除登记、自动补上一块 Wired、手改一块 Endpoint 存盘——那台
下一格就问一次，几秒内那一行就换成新通路的读数，不等它排好的那一次（键盘 2.4G 失联时那是一分钟）。
（spec「换了 Endpoint 集合的那台当场再问」；parking lot Q312 后半、grill 里的 A1。）

- 重读读好了，内核拿新旧两份配置逐台比对 **Endpoint 集合**：Wired、Dongle24G、Ble 三块各自在不在、身份（vid / pid /
  usage / report id，蓝牙地址）变没变。变了的那几台丢掉"下一次什么时候问"，下一格就问。新出现的 Device 今天已经如此。
- `name`、`low_battery`、`level_source`、`driver` 变了不重问；`[general]` 的间隔变了走票 02 的"每一格按此刻的配置算"，
  也不重问。
- **要活过在路上的那一次**：配置换了的那一刻那台的一次取数正在路上（键盘 2.4G 不答要等满 3 秒，用户这时点了"登记到"，
  一两格后重读进来——真机上很常见），那一次的结果回来不许把"当场再问"抹掉：配置换了之后**开始**的那一次取数才算数。
- 一条规则盖住四种来路（菜单登记 / 解除 / 新建、自动补空块、手改），不按"内核知道那一下点了什么"另开口子。本机插拔
  不在此列（spec Out of Scope）。
- 登记设备那一格的模块文档里"登记之后那台下一次什么时候取数照旧"那句随之改口。

**Blocked by:** 02（丢掉的是 02 重做后的那一格；"活过在路上的那一次"要落在它的形状上）

**Status:** ready-for-agent

- [ ] 内核用例：一台走 24G、下一次还有 50 秒才到点，重读进来它多了 `[device.bluetooth]` → 下一格就排它一次取数
- [ ] 内核用例：重读进来一台的蓝牙地址改了、或者 `[device.wired]` 从注释占位变成真块 → 下一格就问；删掉一块 → 也问
- [ ] 内核用例：重读进来只改了 `name`（或 `low_battery`）→ 不多排取数
- [ ] 内核用例：那台有一次取数在路上时重读进来 Endpoint 集合变了 → 那一次回来之后仍然当场再排一次，之后才按新节奏走
- [ ] 内核用例：两台里只有一台变了 → 另一台不被多问
- [ ] `.scratch/manual-acceptance.md`：rt-10"等约一分钟：悬停提示的来源变成 Wired"、rt-11"最多等 60 秒：… 来自 Ble"
      改成"几秒内"
