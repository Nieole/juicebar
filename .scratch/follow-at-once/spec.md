# 改了就当场跟上

Status: ready-for-agent

术语一律按 `CONTEXT.md`（Device / Endpoint / 一次取数 / 一轮 / 上次已知值 / 取数失败 / 暂停 / 短原因 /
完整原因 / 告警 / Primary Device / 保持上次的选择）。相关决策：`docs/adr/0003`（格式保留回写）、
`0004`（坏帧的有界沉默）、`0005`（图标怎么画交给用户选）、`0007`（开机自启走计划任务）、`0008`（成品没有
命令行）。

出处是 2026-09-15 那次 `/grill-with-docs`：第 3 趟 `/settle` 结算出的 8 条无主的活（parking lot Q141、
Q202、Q232、Q251、Q252 连同 Q292 ②、Q312 后半、Q282、Q303、Q348）外加 `resident-tray` 票 15（含并进它的
Q172），磨成一个努力，定了 12 个问题。**本 spec 接管 `resident-tray` 票 15**，那张票标为 `wontfix`、
指向这里。

两条词条随那次会话已经改进 `CONTEXT.md`：「一轮」写明"它的输入变了就开始新的一轮"（配置换了也算，时钟
走一格、图标换样式或调色不算）；「告警」的配置那半句改宽到"启动时就读不了，托盘先空着起来"。

## Problem Statement

托盘已经常驻了，可**用户改了一样东西，托盘要等某台 Device 的下一次取数才照着改**——最长一个轮询间隔，
只配 2.4G 时是 60 秒——而这一分钟正是用户盯着托盘、等着看改动有没有生效的一分钟：

**一、改了配置文件，图标要等一分钟。**手改 `primary`、`low_battery`、一台的 `name` 存盘，配置两秒内就
重读好了，可图标与悬停提示要等某台下一次取数有结果才按新配置排。同一个 `primary` 从菜单里改当场生效、
从文件改要等一分钟——两条路走到同一格，一快一慢。（Q252、Q292 ②）

**二、登记了蓝牙，那一行要等一分钟才从 Ble 来。**菜单里"登记到"点完，配置写回、重读好了，可那台
Device 下一次什么时候问，是上一次取数有结果时算定的；键盘 2.4G 失联时最多等一个 `poll_interval_24g`。
自动补上一块 Wired 也是同一个等法。（Q312）

**三、改了轮询间隔，最多再等一个旧间隔。**"下一次什么时候问"在取数有结果的那一刻按当时的配置算定成一个
时刻，配置换了不重算：把 `poll_interval_24g` 从 3600 改成 60，最多还要等一小时。（Q172）

**四、节奏按答话的那条走，2.4G 反而被问得更勤。**接收器插着、2.4G 不答（鼠标睡了，或者切到了蓝牙档）、
Ble 从缓存答话时，节奏按 Ble 的 10 秒走，可每一次取数照旧先问 2.4G、在唯一的取数线程上等满 3 秒超时：
2.4G 被问得比它该被问的勤 6 倍，其余 Device 的取数也被这 3 秒挡着。spec「轮询节奏」要避开的代价来自
"哪几条**被问了**"，不是"哪一条答了话"。（票 15）

**五、开机时配置写坏了，托盘直接没了。**启动时配置读不了就弹"juicebar 起不来"退出。当初取这条路的前提
是告警在菜单上看不见——那个前提已经没了（告警区在菜单顶上）；而开机自启（ADR-0007）之后，一份写坏的
配置会让托盘登录时悄悄消失，修好之后只能手动启动、再点一次 UAC。（Q251）

**六、暂停期间唯一还答得出话的 Ble 不在场，那一行一个字不提。**真机上暂停那一行的原因列表永远是空的
（只有 Ble 会被真去试，而在场的 Ble 一定读得出），于是"蓝牙地址写错"永远说不出来。取数失败那一支同样：
24G 超时、Ble 配了却地址写错，完整原因只说 24G。（Q141）

**七、几处小尾巴。**"低不低电""算不算充电中"通知与图标状态各写一遍；"已暂停（X 正在运行）"两处各
`format!` 一遍；两份导出脚本约三十行逐字相同、改设计稿要跑两次；首次运行的草稿一个字不提 `[tray]` 那张表
会凭空出现在这里；十三条用例名说的是一条已不存在的命令。（Q202、Q232、Q282、Q303、Q348）

## Solution

**用户改了一样东西——配置文件、菜单里的登记、间隔的数字、关掉了 HUB——托盘当场照着改；节奏照真被问到的
那条通路走。**

1. **配置换了就是新的一轮。**重读读好了，当场按新配置合成一轮、重画图标、重排悬停提示，不等下一次取数。
   菜单里换 Primary Device 早就这样了，现在两条路一样快。
2. **换了 Endpoint 集合的那台当场再问一次。**登记、解除、自动补空块、手改——重读进来某台 Device 的 Endpoint
   块加了、删了、身份换了，下一格就问它，而不是等它排好的那一次。
3. **节奏按这一次真被问到的那几条里间隔最长的那条走**，而且每一格按此刻手上的配置算到没到点：改了间隔
   下一格就生效；2.4G 在场就一分钟最多问一次，不管答话的是谁。
4. **启动时配置读不了，托盘先空着起来**，菜单顶上一行告警说清楚；用户改好存盘，下一格读好、当场合成一轮，
   不必重启、不必再点 UAC。
5. **完整原因点名配了却不在场、而且在场就会被问到的那几条。**暂停那一行说"Ble 不在场（没配对？地址
   写错？）"，取数失败那一句把没插的、没配对的各说各的。
6. **收拾七处小尾巴**：四处重复收成一处，草稿说一句 `[tray]` 从哪来，十三条用例改名，两份脚本合一。

## User Stories

### 配置换了当场跟上

1. 作为用户，我想手改配置里的 `primary` 存盘后图标当场换人，这样从文件改和从菜单改一样快
2. 作为用户，我想改了 `low_battery` 存盘后图标当场按新阈值画，这样我知道改动生效了
3. 作为用户，我想改了一台 Device 的 `name` 存盘后悬停提示与菜单行当场换名字，这样不用盯着等
4. 作为用户，我想配置里新加了一台 Device 存盘后它当场就在菜单里有一行（无已知值），这样我知道它被认出来了
5. 作为用户，我想配置里删掉一台 Device 存盘后它当场从菜单和悬停提示里消失，这样托盘不再画一台不存在的
6. 作为用户，我想由配置开的那一轮也照"保持上次的选择"的规矩记下 Primary Device，这样重启之后还是它
7. 作为用户，我想由配置开的那一轮没有新东西要记时不写状态文件，这样改一次配置不白写一次盘
8. 作为用户，我想程序自己写回配置（换 Primary、改 `[tray]`、登记）之后重读进来的那一轮什么都不重画，这样点一下
   菜单图标不闪一下

### 换了 Endpoint 就当场再问

9. 作为用户，我想在菜单里把蓝牙地址登记到一台 Device 后几秒内那一行就写"来自 Ble"，这样不用等一分钟
10. 作为用户，我想解除蓝牙登记后那台当场再问一次，这样它的读数马上换成别的通路（或者如实写取数失败）
11. 作为用户，我想自动补上一块 Wired 之后几秒内悬停提示的来源就变成 Wired、图标显示充电中，这样插线就见效
12. 作为用户，我想手改一块 Endpoint 的 vid/pid 或蓝牙地址存盘后那台当场再问一次，这样改错了马上看得出
13. 作为用户，我想只改 `name`、`low_battery` 这类不碰 Endpoint 的键时不多问一次 2.4G，这样改个名字不多耗设备的电
14. 作为用户，我想配置换了的时候那台正好有一次取数在路上，它回来之后仍然当场再问一次，这样点了登记不会因为
    时机不巧而要等一分钟

### 节奏照真被问到的那条走

15. 作为用户，我想接收器插着、2.4G 不答、Ble 答话时 2.4G 仍然一分钟最多被问一次，这样它不因问得太勤而多耗电
16. 作为用户，我想其余 Device 的取数不被一台不答话的 2.4G 每十秒挡三秒，这样菜单里别的行不跟着卡
17. 作为用户，我想 HUB 在跑、2.4G 让开、只问了 Ble 时节奏按 Ble 的 10 秒走，这样暂停期间 Ble 照常更新
18. 作为用户，我想 HUB 关了之后下一次问到 2.4G 时节奏回到 60 秒，这样暂停结束后不再多问
19. 作为用户，我想 Wired 在场却读坏、落到 2.4G 答话时按 2.4G 的间隔再问，这样 2.4G 不被 Wired 的节奏带着问
20. 作为用户，我想改了配置里的轮询间隔存盘后下一格就按新间隔算，这样"3600 改成 60"不用再等一小时
21. 作为用户，我想一条 Endpoint 都没试到（一条都不在场、本机枚举不了）时节奏照今天的兜底走，这样拔了接收器
    的设备不被多问
22. 作为用户，我想 HID 那两条的陈旧阈值仍是它们自己间隔的 3 倍，这样节奏改了陈旧判定不跟着漂

### 启动时配置读不了

23. 作为用户，我想开机自启时配置写坏了托盘照样出现在通知区，这样它不会悄悄消失
24. 作为用户，我想启动时配置读不了、右键菜单最顶上有一行说"读不了配置文件，托盘先空着起来"，这样我知道它为什么空着
25. 作为用户，我想点那一行打开日志看到完整的 TOML 错误，这样知道哪一行写坏了
26. 作为用户，我想此时"打开配置文件"照样能用，这样不用自己去找文件
27. 作为用户，我想改好存盘后下一格就读好、告警消失、设备行出现、每台各问一次，这样不必重启、不必再点 UAC
28. 作为用户，我想启动时读不了那句告警与运行中读不了那句（"沿用上一份读好的"）是两句话，这样菜单上不说假话
29. 作为用户，我想写不进草稿、读不到 `APPDATA` 时仍然弹"juicebar 起不来"，这样连日志都写不了的情形不被咽掉
30. 作为用户，我想空着起来的那几分钟悬停提示照旧说"一台 Device 都没有"那句，告警只住在菜单里，这样悬停提示
    不开始替告警说话

### 完整原因点名配了却不在场的

31. 作为用户，我想暂停那一行在 Ble 配了却不在场时接一句"；配了却不在场：Ble（没配对？地址写错？）"，这样我知道
    暂停期间为什么连 Ble 都没顶上
32. 作为用户，我想暂停那一行不提没插的 Wired，这样它不叫我去做一件暂停期间没用的事
33. 作为用户，我想取数失败"试过了都失败"那一句末尾点名配了却不在场的每一条（HID 的问"没插？"，Ble 的问
    "没配对？地址写错？"），这样 24G 超时、蓝牙地址写错两件事都说出来
34. 作为用户，我想"一条都不在场"那句照旧，这样它已经点名的不再说第二遍
35. 作为用户，我想菜单那一行的短原因一个字不变，这样一行菜单仍然放得下

### 小尾巴

36. 作为用户，我想首次运行的草稿在 `[general]` 之后有两行注释说 `[tray]` 在托盘菜单里改、程序会写回到这里，这样
    打开文件的人知道那张表会从哪来
37. 作为开发者，我想"低不低电""算不算充电中"只在一处判，这样通知与图标状态答的永远是同一个问题
38. 作为开发者，我想"已暂停（X 正在运行）"只在一处定，这样三份抄本不会漂开
39. 作为开发者，我想改完设计稿跑一份脚本就更新全部基准，这样不会只导了一半
40. 作为开发者，我想 `tests/config.rs` 里自动补空块的用例名说的是这个功能，而不是一条已不存在的命令，这样下一个读的
    人不去找它

## Implementation Decisions

### 一轮由配置开始

- 「一轮」的开始方式按新词条：**它的输入变了就开始新的一轮**——任一台 Device 的一次取数有了新结果，或者手上
  那份配置换了（重读读好了，菜单里换了 Primary Device）。时钟走一格（parking lot Q164）、`[tray]` 换了样式
  （Q300）、任务栏深浅与缩放换了（Q261）只重画，不是新的一轮：它们不改一轮的输入。
- 重读读好了：换掉手上那一份、摘掉"配置读不了"、新登记的 Device 记成无已知值，然后**当场合成一轮**——走菜单
  换 Primary Device 今天走的那条路，"当下"取手上最近的那一刻（上一格时钟或上一次取数）。
- **状态文件照菜单那一头的规矩**：由配置开的那一轮没有新读到的东西要记，选出的 Primary Device 换了人才存、
  记 `last_primary`（钉死选出的也记，Q292 ①）；没换就一个字节不写。
- 程序自己写回之后重读进来的那一轮，合成的结果与画着的一样，图标与悬停提示都不重发（内核今天就按"一样的
  不再发一遍"守着）。
- 重读读不了（`Reloaded(Err)`）不开一轮：手上的配置没换，告警挂上就够——悬停提示不读告警。

### 换了 Endpoint 集合的那台当场再问

- 重读读好了，内核拿新旧两份配置逐台比对**Endpoint 集合**：Wired、Dongle24G、Ble 三块各自在不在、身份（vid /
  pid / usage / report id，蓝牙地址）变没变。变了的那几台丢掉"下一次什么时候问"，下一格就问。新出现的 Device
  今天已经如此。
- `name`、`low_battery`、`level_source`、`driver` 变了不重问。`[general]` 的间隔变了走下面"每一格按此刻的配置算"，
  也不重问。
- **要活过在路上的那一次**：配置换了的那一刻某台的一次取数正在路上（键盘 2.4G 不答要等满 3 秒，用户这时点了
  "登记到"，一两格后重读进来，这个时序在真机上很常见），那一次的结果回来不许把"当场再问"抹掉——配置换了之后
  **开始**的那一次取数才算数。
- 一条规则盖住四种来路（菜单登记 / 解除 / 新建、自动补空块、手改），不按"内核知道那一下点了什么"另开口子
  （Q312 的另一条路被否）。本机插拔不在此列（见 Out of Scope）。

### 节奏按真被问到的那几条

- 一次取数交回**这一次问过哪几条 Endpoint**（`tried`）：按优先级真去试了的那几条，包括答了话的那条；让开的
  那几条不算（压根没问）；一条都不在场、本机枚举不了时是空的。取数那一层的结果连同它一起交到内核。
- 节奏这一块每台记的不再是"下一次的时刻"，而是**上一次取数的时刻 + 那一次问了哪几条**；时钟每走一格，按内核
  **此刻**手上的配置算间隔——`tried` 里各条间隔取最长的那个——到没到点。配置换了下一格就按新的算（Q172）。
- `tried` 为空沿用今天的兜底：按配置里优先级最高的那条；一条都没配的按三个间隔里最长的（Q170）。
- 陈旧判定不动：HID 那两条仍按各自读数来自的那条 Endpoint 间隔的 3 倍，节奏取的间隔与它出自同一处。
- spec「轮询节奏」那一段就此改写；`resident-tray` 票 05 与票 15 的口径由这里取代。退避（2.4G 没答就一阵只问
  Ble）不做，见 Out of Scope。

### 启动时配置读不了

- 文件在、却读不了（写坏、读不到）：外壳拿一份空配置起来，交回"启动时就读不了"那一个事件（与首次运行交回
  "草稿写好了"同一个口子），内核收到就挂告警。用户改好存盘，下一格重读读好、摘掉告警、按上面的规矩当场合成
  一轮，每台各问一次。
- 写不进草稿、读不到 `APPDATA` 仍然弹"juicebar 起不来"：那时连日志都写不了。
- 告警是**同一件事（配置文件）的两种说法**：运行中读不了仍是"读不了配置文件，沿用上一份读好的"；启动时读不了
  是"读不了配置文件，托盘先空着起来"。两种挂在同一格上，读好了都摘掉。完整原因照旧进日志，点那一行打开日志。
- 悬停提示不动：空着起来那几分钟照旧说"一台 Device 都没有"那句，告警只住在菜单里。
- 内核这一侧的告警变体形状（同一个 `Matter`）由实现定；`CONTEXT.md`「告警」已经改宽。

### 完整原因点名配了却不在场的

- 规则：**配了、不在场、而且在场就会被问到的那几条**。一次取数把它们收集起来，完整原因（`Display`）末尾接一句
  "；配了却不在场：…"，每一条带自己那种的问句——HID 的"没插？"，Ble 的"没配对？地址写错？"。
- 暂停那一支：让开的是 Wired 与 Dongle24G，所以在场也不会被问的 HID 不点名，只剩 Ble。
- 取数失败"试过了都失败"那一支：哪条在场都会被问，全部不在场的都点名。
- "一条都不在场"那一句已经点名了，不变；"一条都没配"那句无从点名，不变。
- 短原因（菜单那一行）一个字不动；`CONTEXT.md`「暂停」不动（它说的"Ble 照常更新"以在场为前提，这句是把前提
  说出来）。

### 小尾巴

- **Q202**：`DeviceState` 上加"低不低电""算不算充电中"两个方法，`Level` 加 `percent()`；图标状态、通知、悬停提示都
  来问它。行为不变，用例不动。
- **Q232**："已暂停（X 正在运行）"收成 `VendorHub` 上一个方法，短原因与悬停提示都来问它。输出一个字不变。
- **Q303**：草稿在 `[general]` 之后写两行注释，大意"`[tray]` 图标样式与菜单显示：在托盘右键菜单里改，程序会写回到
  这里；各键的含义见 `config.example.toml`"。不写那八个键（它们在菜单里都看得见、点得动，Q303 原来那条前提
  已不成立）。
- **Q348**：十三条 `config_refresh_*` 用例改成 `auto_fill_*` 前缀，"fill fills"撞车的几条换个动词。`config::refresh`
  函数名、`Refreshed` / `RefreshNote` 不动。
- **Q282**：两份导出脚本合成一份 `tests/export_baselines.mjs`：起一次浏览器分别打开两个锚点，各自的 JSON 写进各自的
  目录；任一像素认不出调色板就两个目录都不写。基准文件、比对它们的用例、设计稿页底的两个锚点都不动；
  `preview-gray.txt` 留在原处。

## Testing Decisions

好的测试只测外部行为，不测私有函数——这个仓库用集成测试，让编译器守着这一条。

**四道缝，全是现成的**（写 spec 时与用户确认过）。

- **托盘内核**（`tests/tray_*.rs`，假时钟 + 罐装的一次取数结果）：
  - 重读读好了当场合成一轮：改 `primary` 图标换人、改 `low_battery` 图标换状态、改 `name` 悬停提示换名；选出的
    换了人就存状态文件、没换就不存；程序写回后重读进来什么都不重发；读不了不开一轮
  - Endpoint 集合变了的那台下一格就问，只改 `name` 的不问；一次取数在路上时配置换了，它回来之后仍然再问一次
  - 节奏：24G 在场不答、Ble 答话按 60 秒；暂停只问了 Ble 按 10 秒，HUB 关了问到 24G 回到 60；Wired 读坏落到 24G
    按 60；改了间隔下一格就按新的；`tried` 为空走兜底；陈旧阈值仍是 3 倍
  - 启动时读不了那个事件：挂上"托盘先空着起来"那一条，读好了摘掉、设备行出现、每台各问一次；运行中读不了
    仍是"沿用上一份"那一句
  - `Fetched` 多带 `tried`，harness 里造它的帮手跟着带。prior art：`tests/tray_cadence.rs` 那批用假时钟走节奏的
    用例、`tests/tray_config.rs` 那批喂 `Reloaded` 的用例。
- **取数那一层**（`tests/readout.rs`，假 `Endpoints`）：`tried` 的内容（含让开的不算、一条都不在场为空）；暂停那一支
  只点名 Ble、取数失败那一支点名全部不在场的、"一条都不在场"那句不变。prior art：现有对完整原因确切字符串的断言。
- **配置文本**（`tests/config.rs`）：草稿那两行注释在 `[general]` 之后、`[[device]]` 之前；十三条用例改名后照旧全绿。
- **导出脚本**没有 Rust 用例：验收是跑一次 `node tests/export_baselines.mjs`、两个基准目录 `git diff` 为空。
- **外壳不做自动测试**（`ConfigFile::open` 与 `run()` 里那几行），归手工验收：启动前写坏配置 → 托盘出现、菜单顶上
  那一行、改好存盘后恢复。
- gate 三条（`fmt --check`、`clippy --all-targets -D warnings`、`test`）全绿。**本机（Linux）编不了 windows 系列
  crate，`cargo test` 只能在 Windows 上跑。**

## Out of Scope

- **2.4G 没答就退避一阵、只问 Ble**（票 15 的方向 b）：按新节奏一台不答话的 2.4G 每 60 秒最多挡别的取数 3 秒，
  先不做；真嫌它挡再开。
- **本机插拔（`DevicesChanged`）也当场再问**：第一次插线自动补空块本身就改了配置、按本 spec 已经当场问；之后再
  拔插等一个间隔可以接受。
- 悬停提示替告警说话（Q9 的 (b)）。
- 改 `config::refresh` 这个函数名与 `Refreshed` / `RefreshNote`（59 处，不是纯改名）。
- 把 `preview-gray.txt` 搬进 `icon_baselines/`。
- 草稿写出 `[tray]` 八个键。
- 运行中配置文件被删掉重新生成草稿（Q253 维持）。

## Further Notes

**不落 ADR。**四个决定（配置开一轮、节奏按被问的、空着起来、点名不在场的）翻起来都关在两三个文件里，过不了
"难以翻案"那一条门槛；词条改在 `CONTEXT.md`，理由写在各自模块文档与本 spec。

**第二堆为什么没写成"谁改到就顺手"**：`docs/agents/queue-conventions.md` 立的是反面的规矩（路过的缺陷记下来
别顺手改），一句"谁改到就顺手"与它正面相抵，而且把一份待办清单塞进了一份规矩文档。四条行为不变的收拾
（Q202、Q232、Q282、Q348）收成这个努力开头的一张 prefactor 票，没有 blocker、排第一：它动的正是后面几张
要动的文件，先落地后面的票就在收拾干净的地方写。

**名字**：叫 `follow-at-once`，中文「改了就当场跟上」：它建的是"用户改了一样东西，托盘当场照着改"，不是
它从哪个抽屉来的。
