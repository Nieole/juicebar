# 手工验收清单：常驻托盘与菜单照设计稿

**来源**：2026-09-10 至 09-15 那一趟实现队列（`resident-tray`、`menu-as-designed`、`screen-as-a-function`）。
队列里每张带"手工验收"的票，那一格都没勾，统一交到这里：托盘本体要管理员权限，菜单、图标、通知要人眼看，
agent 在这台机器上验不了。

**怎么用**：做完一节，勾上这里的框，再回到对应票面把"手工验收"那一格勾上。`menu-as-designed` 票 07 的第四格
（截图对不上的结论）要回填结论。发现不对的，记进 `.scratch/parking-lot.md` 或者直接告诉 Claude。

## 准备（做一次）

- [ ] 在仓库根目录编最新版：`cargo build --release`。下面说的"启动托盘"都是双击
      `target\release\juicebar.exe`（会弹 UAC，点"是"）。
- [ ] 右键原来那个托盘点"退出"。单实例已经做了：再启动一个只会弹"已经在托盘里了"。
- [ ] 备份配置与状态文件（PowerShell）：
      `Copy-Item "$env:APPDATA\juicebar\config.toml" "$env:APPDATA\juicebar\config.toml.bak"`，
      `state.toml` 同样。每一节做完用备份还原，下一节从干净状态开始。
- [ ] 记下此刻的深浅设置（设置 → 个性化 → 颜色）与显示缩放，全部做完后恢复。
- [ ] 建议顺序：rt-14 → rt-04 → rt-06 → rt-07 → mad-02 → mad-03 → rt-08 → rt-09 → rt-10 → rt-11 → rt-12
      → rt-13 → mad-07。开机自启要重启，放在后面；截图对照最费时，放最后。

## resident-tray 14：只剩托盘一个程序

- [ ] 双击 `juicebar.exe`：弹 UAC，托盘出现图标。
- [ ] 右键"退出"，再在终端里跑 `target\release\juicebar.exe status`：弹 UAC，起来的也是托盘，终端里不印字
      （子命令已经没有了）。
- [ ] 普通终端 `cargo run --example scan` 照旧列出本机设备；管理员终端里跑 `cargo run --example probe -- …`
      照旧能发帧。

## resident-tray 04：托盘贯穿线

- [ ] 双击：弹 UAC（"未知发布者"），不闪黑框；点"否"什么都不起。
- [ ] 点"是"：通知区出现图标（可能在 `^` 溢出区里）。第一次取数回来之前，状态文件里有旧值画灰数，没有画 `--`。
- [ ] 几秒内换成 Primary Device 此刻的样子。
- [ ] 悬停：名字 / 电量（带 Reported Level 或 Derived Level）/ 来自哪条通路（N 秒前）；半分钟后 N 变大。
- [ ] 插线充电或电量变化后，一分钟内图标与悬停跟着更新。
- [ ] 右键 → "退出"：图标立刻消失，几秒内进程结束。
- [ ] 任务管理器里重启"Windows 资源管理器"：图标自己回来。
- [ ] `%APPDATA%\juicebar\juicebar.log` 里有"托盘启动"与"退出"；拔掉 dongle 等一分钟，出现
      "… 取数失败，退到上次已知值：…"并带完整原因。
- [ ] 取数之后 `state.toml` 被更新，`last_primary` 就是图标上画的那一台。

## resident-tray 06：设备行与"托盘上画哪一台"

- [ ] 右键一级次序：设备行 → 分隔线 → 托盘上画哪一台 › → 图标样式 › → 菜单显示 › → 登记设备 › → 开机自启
      → 分隔线 → 打开配置文件 → 退出。
- [ ] **拍板 Q290**：设备行右列写的是"57%（Reported Level）"（与悬停提示同一句）。看一眼菜单宽度能不能接受；
      想只写"57%"就告诉 Claude。
- [ ] 一台正常：写"名字  来自 Dongle24G（N 秒前）"，右列有电量，不变灰；Primary Device 那一行打勾。
- [ ] 一台读不到（拔接收器或关机，等它下一次取数）：那一行变灰，中段"失联（没插？没配对？没开机？）"；
      手上有上次已知值时右列照样写电量。
- [ ] 告警：把 `config.toml` 写坏一处存盘，一两秒内菜单最顶上出现"读不了配置文件，沿用上一份读好的"；
      点它，默认程序打开 `juicebar.log` 看到完整原因；改回存盘，告警消失。
- [ ] "托盘上画哪一台 ›"点另一台：图标当场换人，子菜单右列变成那台的名字，圆点跟着挪；再点
      "自动（电量最低）"：当场回到电量最低的那台。
- [ ] 每次切换后 `fc config.toml.bak config.toml`：只有 `primary = ` 那一行不同，注释都在。
- [ ] 还原配置。

## resident-tray 07：图标样式与菜单显示

- [ ] 一级"图标样式"那一行右边不写字；第二层六行右边写当前值，末尾"恢复默认"。
- [ ] 最里一层：每个选项前面有预览，**当前项加粗、不画圆点**；缺省项写"默认"，B 电池写
      "16、20 像素不显示数字"；"灰状态"是三张并排。
- [ ] **预览没有上下颠倒**：D 的底条在数字下面，C 圆环从 12 点起顺时针（150% 或 200% 缩放最清楚）。
- [ ] 20 个选项各点一次：托盘图标当场换样子；`config.toml` 与备份比只有那一个键那一行变了；再打开菜单，
      加粗挪到刚点的那一项。
- [ ] "恢复默认"：图标回到缺省样子，改过的图标键写回缺省值，`menu_source` 与 `primary_mark` 不动。
- [ ] "菜单显示"：关掉"写出来源和多久前"→ 有读数的行只剩名字与电量，读不到的行照样写短原因；关掉
      "标出 Primary Device"→ 设备行不再打勾。
- [ ] 手改一个错值 `style = "squre"`：图标按缺省画，日志里有一句"认不出，按缺省值 "bar" 处理"。
- [ ] 托盘开着切一次 Windows 模式深浅：图标当场换调色；菜单与预览都跟任务栏的深浅一致。
- [ ] **核 Q301**：不注销，把缩放从 100% 改到 150%：图标清晰地换成 24 像素一档（不是被拉糊），预览变成
      24 像素、菜单项变高。没换档的话把结果告诉 Claude（记回 Q301）。看完改回。
- [ ] 还原配置、深浅与缩放。

## menu-as-designed 02：位图交给 Windows

      没有发白。
- [ ] 切浅色任务栏，图标重画，照上一步再看一次。

## menu-as-designed 03：菜单深浅跟任务栏

- [ ] Windows 模式深色 → 右键：菜单是深色。
- [ ] Windows 模式浅色 → 右键：菜单是浅色。
- [ ] Windows 模式深 + 应用模式浅 → 右键：菜单仍是深色（原型已在实机证实强制深色压得住，这一步验的是产品代码）。
- [ ] 托盘开着把 Windows 模式深 ↔ 浅来回切：下一次右键，菜单跟着换。
- [ ] `juicebar.log` 里不应有"菜单跟不上任务栏的深浅"；最后点"退出"确认能退出。

## resident-tray 08：低电通知（碰真配置）

- [ ] 关掉 VGN HUB（它在跑时只配 2.4G 的设备退到上次已知值，按规则不提醒）；被测设备别插线；确认没开勿扰或专注助手。
- [ ] 把 `[general]` 的 `low_battery` 改成高于当前电量（例如 90）；那台 `[[device]]` 自己写了 `low_battery`
      就改它那一行。先改配置，再启动托盘。
- [ ] 几秒内弹通知：标题"<设备名> 电量低"，正文形如"62%（Reported Level），低于低电量阈值 90%"；每台低于阈值的
      各一条。
- [ ] 什么都不动，等 3 分钟以上：不再弹第二条。
- [ ] （可选）退出再启动：再弹一次。
- [ ] 还原配置。

## resident-tray 09：配置重读与首次运行（碰真配置）

- [ ] 右键"打开配置文件"：默认程序打开 `config.toml`（编辑器继承管理员权限，属正常）。
- [ ] 改一台设备的 `name` 保存：约 2 秒内悬停提示里的名字变了；改 `low_battery = 90`：下一次取数后图标画成低电。
- [ ] 删掉一个 `]` 保存：约 2 秒内日志多**一行**"读不了配置文件，沿用上一份读好的 —— …"带完整 TOML 错误，
      菜单顶上出现告警；托盘照常，不每秒重复记。
- [ ] 补回 `]` 并改一下 `name` 保存：新名字生效，菜单顶上的告警消失。
- [ ] （可选）运行中把 `config.toml` 挪走：日志记一行，托盘不停；挪回来恢复。
- [ ] 退出 → 把 `config.toml` 挪走 → 启动：在 `%APPDATA%\juicebar\` 生成草稿，弹"已生成配置 / 右键托盘图标，
      点'打开配置文件'看一眼"，图标出现并开始轮询；"打开配置文件"打开的是这份草稿。
- [ ] （可选）启动前把配置写坏：弹"juicebar 起不来：…"（parking lot Q251 定的行为）。
- [ ] 还原：退出、删掉草稿、两个备份拷回，确认 `config.toml` 回到原来的大小。

## resident-tray 10：自动补空块（碰真配置与真设备）

- [ ] 拔掉鼠标的线；确认配置里 dragonfly3 的 `[device.wired]` 只是注释占位（已经是真块就先删掉那几行，退出再启动）。
- [ ] 启动时没有动静：不弹通知，配置文件的修改时间不变。
- [ ] 托盘开着插上鼠标的线，几秒内：通知"配置已自动更新 / 补上了 Dragonfly 3 Master+ 的 Wired"；日志多一行
      "自动补空块 —— dragonfly3：补上了 Wired（…）"；`fc` 比对只多了 `[device.wired]` 那几行。
      **没弹的话（核 Q270）**：日志里有"登记不了设备插拔的通知"是登记失败；没有这一行，就是提权之后收不到插拔消息。
- [ ] 等约一分钟：悬停提示的来源变成 Wired，图标显示充电中。
- [ ] 再拔插一次线：不弹通知，文件修改时间不变。
- [ ] 退出 → 删掉刚补上的 `[device.wired]` → 线插着启动：弹同一条通知，块被补回。
- [ ] 还原配置。

## resident-tray 11：蓝牙登记与解除（Neon75；碰真配置）

- [ ] 前提：Neon75 在"蓝牙和设备"里已配对，并用蓝牙档连上过一次；配置里 neon75 还没有 `[device.bluetooth]`。
- [ ] 启动后等十来秒，右键 → 登记设备 ›：有 Neon75 的蓝牙名，右列 `Ble`；它的"登记到 ›"里有 VGN Neon75；一级
      设备行没有多出这台蓝牙设备。
      **没出现的话**：多半是 Windows 没缓存它的电量属性（rt-11 查出的缺口：列表只列 Windows 有电量缓存的蓝牙设备）。
- [ ] 点 登记到 › VGN Neon75：日志有"登记设备 —— 把蓝牙地址 … 登记到 neon75"；配置里 neon75 只多了三行
      （空行、`[device.bluetooth]`、`address = "…"`）。
- [ ] 一两秒后右键：那台蓝牙设备从"登记设备 ›"里消失，出现"解除蓝牙登记 › VGN Neon75"，右列是地址。
- [ ] 最多等 60 秒：一级 VGN Neon75 那一行写"来自 Ble（Windows 缓存，… 前）"，右列有电量。
- [ ] 点 解除蓝牙登记 › VGN Neon75：日志多一行"解除 neon75 的蓝牙登记"；`fc` 比对与备份完全相同；那台蓝牙设备
      回到"登记设备 ›"。
- [ ] 还原配置。

      `name`、`driver = "vgn_keyboard"` 与 `[device.wireless_24g]`，其余与备份逐字节相同；一级重新出现它并读到电量；

## resident-tray 13：单实例与开机自启（要重启）

- [ ] 右键确认"开机自启"缺省没勾；勾上后打开 `taskschd.msc`，库根下有 `juicebar` 任务：登录时触发、只针对当前
      用户、"使用最高权限运行"、程序指向这次运行的 `juicebar.exe`、"只有在计算机使用交流电源时才启动"没勾、
      没有 72 小时时限；日志有"开机自启已打开 —— … 启动 <路径>"。
- [ ] 重启并登录：不弹 UAC，图标出现。
- [ ] 再手动双击启动一次（会弹 UAC）：老实例弹"已经在托盘里了"，托盘里仍然只有一个图标，第二个进程已经退出。
- [ ] 开机后低电通知不丢（Q204）：先把 `low_battery` 调得比当前电量高，重启，看通知照样弹出来。
- [ ] 取消"开机自启"：`taskschd.msc` 里任务没了，日志有"开机自启已关掉"，再右键不勾。
- [ ] 还原配置。
