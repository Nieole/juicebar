# 这一屏成为一个函数

Status: ready-for-agent

四块内容，共一个形状：**上一趟买的是那一行说的是不是实话，这一趟买的是说这句话的东西有没有
名字和形状。** 术语一律按 `CONTEXT.md`（Reading / Stale / Unknown / 失联 / 读取异常 / **取数失败** /
暂停 / 上次已知值 / Primary Device）。相关决策见 `docs/adr/0001`（接收器有自己一组 VID/PID）与
`docs/adr/0004`（坏帧时取有界的沉默）。

出处是第 2 趟 `/settle` 结算出来的 Q69、Q88、Q89、Q91，磨制过程见 `.scratch/homeless-2.md`。
**词汇已经先行**：「取数失败」这一条在磨这份 spec 的过程中一落定就写进了 `CONTEXT.md`。

## Problem Statement

**一、这一屏没有形状。** `run()` 一个函数里装着四样不相干的事：构造真系统（枚举 HID、取时钟、
读状态文件、探测厂商上位机）、逐台取数、合成那几行、打印。而 `render` / `primary_lines` /
`unregistered_ble_lines` / `DeviceRow` 四个 `pub` 在 `src/` 里**一个非测试调用方都没有** ——
它们 `pub` 的唯一理由是 `run` 测不到，而 `run` 测不到是因为它要真去枚举本机 HID 通路。

代价不是难看，是**有一批行为今天谁也测不到**，而且每一条都是这个仓库明确在意的那种：

- 进程枚举失败时**按"没在跑"走、只在 stderr 说一句**（fail open）。反过来会让一台 Win32 调用
  失败的机器永久显示"暂停中"、指名一个没在跑的进程 —— 一句查不下去的假话。这条规则第 1 趟
  `/settle` 的 Q34 就记着测不到。
- 「配置 … 里一个 Device 都没有。」那一行，以及**它之后不提前 return** 这个决定（那正是最需要
  未登记 BLE 名单的时刻）。
- 未登记 BLE 那一段的标题、空行与缩进。
- **「选出了 Primary 才记、选不出来什么都不动」** —— "保持上次的选择"整条线就挂在这一句上，
  而它断了不会红，只会悄悄永远选不出来。

**二、取数失败没有名字。** `CONTEXT.md` 有「失联」（去问了、问不到）与「读取异常」（设备答了话、
那一帧不可采信），**却没有一个词指它们的上一层**。于是代码里那个变体叫 `Lost`／失联，而它今天
装着读取异常 —— 「读取异常」的 _Avoid_ 明写着不许这么用。两处文档（Primary 选择里的候选读数、
一行 Device 的成品）只好拿"失联"当上位词使，因为没有别的词可用。

**三、暂停那一支许了一个兑现不了的承诺。** 原因列表为空时那一行接的是「，关掉它就会恢复」，
而**列表为空只说明这一趟什么都没试过**。接收器插着、设备本体关了机的那一趟正是这一支：接收器
有自己一组 VID/PID（`docs/adr/0001`），所以 Dongle24G 照样在场、照样被让开、列表照样是空的。
关掉上位机之后那条通路仍旧超时。**这与上一趟要治的病同形**：那一行断言它不知道的事。

**四、用户可见的长字符串没有写法。** 这个仓库用续行符折这类字符串已经栽过两次，两次都是续行符
丢了、把源码里的缩进空格印给了用户：一次已修，另一次还在（`probe` 那句"没有匹配的 collection"
里有 13 个字面空格）。而 `/code-review` 的 Standards 轴找的是仓库里记载"代码该怎么写"的文件
—— **本仓库一条成文标准都没有**，那条轴至今只跑在 Fowler 的气味基线上。

## Solution

1. **整屏成为一个函数。** 新模块承接呈现那一半，交出一个"这一屏印成什么样"的函数：它自己探测
   厂商上位机、自己写状态文件的那两处、自己造每一行（包括空配置那一句），返回**两个输出流**
   的内容。`run` 退成一个壳 —— load、构造、调它、把两个流分别送 stdout 与 stderr、save。
2. **取数失败有了名字。** 那个变体改名成一个不宣称失联的中性名，`CONTEXT.md` 收下「取数失败」
   这一条（三种来路：失联、读取异常、配置里一条 Endpoint 都没有），两处文档改口。
3. **那句承诺降格成条件句** —— 说我们会做什么，不说设备会怎样。
4. **那些话怎么写成文。** 新开一份编码标准，第一条就是它；`probe` 那处洞顺手收掉，这一类从此
   归零。

## User Stories

1. 作为用户，我想在厂商上位机认不出来的那一趟仍然看到正常的几行、而不是一句指名了一个没在跑的
   进程的"暂停中"，这样一次 Win32 调用失败不会变成一句我查不下去的假话
2. 作为用户，我想那条 fail-open 规则**有用例守着**，这样它不会在下一次重构里被悄悄改成反过来
3. 作为用户，我想配置里一个 Device 都没有时仍然看到未登记的 BLE 名单，这样我能直接从那几行里
   把 MAC 抄进配置 —— 那正是我最需要它的时刻
4. 作为用户，我想"选出了 Primary 才记"这条规则有用例守着，这样"保持上次的选择"不会某天悄悄
   永远选不出来
5. 作为用户，我想未登记 BLE 那一段的标题、空行与缩进有用例守着，这样它不会在下次改动里排乱
6. 作为用户，我想这次搬家**一个字的输出都不变**（除了下面第 7、8 条点名的两处），这样我不必
   重新认屏幕
7. 作为用户，我想暂停那一行不再承诺"关掉它就会恢复"，这样接收器插着而设备关了机的时候，程序
   不会许一个它兑现不了的诺
8. 作为用户，我想 `probe` 那句提示里不再有一截莫名其妙的空格，这样那句话读起来像句话
9. 作为用户，我想暂停那一行仍然点名那个上位机、仍然告诉我该关掉它，这样我唯一能据以行动的
   东西没有因为措辞变准而丢失
10. 作为用户，我想暂停那一支在"剩下的也没读到"那一种上一个字不变，这样这次改动只碰它该碰的
    那半句
11. 作为读代码的人，我想**取数失败**在词汇表里有定义，这样我不必拿"失联"去指一个比它宽的概念
12. 作为读代码的人，我想那个变体的名字不宣称"失联"，这样我不会在一个叫失联的变体里撞见读取异常
    —— 而词汇表恰恰明写着不许这么指
13. 作为读代码的人，我想 Primary 选择那一处与一行 Device 那一处的文档跟着改口，这样词汇表、
    类型名、文档三处说的是同一件事
14. 作为读代码的人，我想 `src/cli/` 下每个文件都只是一条子命令的壳，这样我不必在一个子命令
    文件里找领域逻辑
15. 作为读代码的人，我想那几个 `pub` 的文档说清它是**什么**的接口，而不是说"为了测试"，这样
    公开面读起来是一个决定而不是一个妥协
16. 作为下一个动这一层的人，我想"这一屏印成什么样"是一个纯函数，这样我改它时有地方下手断言
17. 作为下一个动这一层的人，我想 `run` 短到一眼看完，这样我知道那道躲不开真系统的墙到底有多厚
18. 作为下一个写用户可见字符串的人，我想有一条成文规矩告诉我长句怎么写，这样我不必再猜，也
    不会第三次踩进同一个坑
19. 作为审这次改动的人，我想搬家那一块的 diff 是**纯移动**，这样我一眼核得完
20. 作为审这次改动的人，我想 `/code-review` 的 Standards 轴终于有本仓库自己的出处可引，这样它
    不再只有一份通用的气味基线
21. 作为在并行 worktree 里做这几张票的 agent，我想它们碰的文件相交之处被写明白，这样合并不会
    打架

## Implementation Decisions

### 呈现那一半的接缝

- **新模块承接呈现**：`render` / `primary_lines` / `unregistered_ble_lines` / `DeviceRow` 全部
  搬过去，加上整屏那个函数与它的返回类型。**取名 `screen`**（不叫 `display` —— `Display` 在
  Rust 里已经有含义；也不叫 `presentation` —— 交出去的东西就叫"这一屏"）。搬完之后 `cli::status`
  只剩 `run`，与它的邻居（caps / config_refresh / probe / scan）同一个量级 ——
  **`src/cli/` 从此每个文件都只是一条子命令的壳**。这是 `readout` 那次搬家的第二步，同一条路。
- **整屏那个函数收什么**：配置路径、配置、Endpoint 枚举、Clock、Processes、可变的上次已知值。
  Clock **整个**进（每台设备各取一次"当下"，不能只收一个时刻）；Processes **整个**进（不是收
  探测结果）—— 那条 fail-open 规则因此一起进了可测范围。
- **返回两个输出流**：一份是要印到 stdout 的那几行，一份是要印到 stderr 的告警。函数**自己不印**。
  两个输出流本来就是这一屏的真实形状，藏起来只会让 `run` 继续有一段没人看得见的行为。
- **状态文件的两处写入都在里面**：记读数（今天已经在取数那一步里）与记 Primary。`run` 只管两端
  的 load 与 save。同一份状态不分给两个人管 —— 那条线断了不会红。
- **空配置那一行也在里面**，所以函数要收配置路径。**`run` 从此不自己造任何一行。**
- **`run` 退成壳**：解析路径 → 不存在则走 bootstrap → load → 构造四样真东西 → 调它 →
  两个流分别打印 → save。
- **公开面**：整屏那个函数、`render`、`primary_lines`、`DeviceRow` 是模块的公开面，
  **它们的文档要说清各自是什么的接口** —— `render` 是「一行」的、`primary_lines` 是「哪一行挂
  Primary 标注」的。`unregistered_ble_lines` **收私有**（它是这一屏的一段，不是一个概念），
  它那几条用例改从整屏驱动。
- **不写 ADR。** `docs/adr/` 今天四条全是产品／协议决定，没有一条是代码结构的；开一条结构类
  ADR 会把那个目录的定义拓宽，此后每次模块划分都得掂量要不要写。**这道缝的理由进新模块的文档头**
  —— `readout` 那次就是这么办的。

### 取数失败的名字

- **变体改名**成一个中性名（推荐 `Failed`），它与暂停那个变体切成一条干净的二分：**取数失败**
  对 **主动让开**。**payload 不动** —— 不加取数失败的分类枚举（`docs/adr/0004`）。
- **`CONTEXT.md` 的「取数失败」已经落地**，词条把"配置里一条 Endpoint 都没有"也收了进来：
  那一支今天就在这个变体里、在那一行上，不收进来的话类型又一次比词条宽，而那正是这一条要治的病。
- **两处文档改口**：Primary 选择里那份候选读数的 `None`、一行 Device 成品里那个 `candidate` 的
  `None`，今天都写着"失联"，改成"取数失败"。

### 暂停那句话

- 原因列表为空那一支的后半句改成**「，关掉它之后这几条才试得到」** —— 说的是我们的动作，不是
  设备的反应，行动指引一个字没丢。**列表非空那一支一个字不动**（它本来就不承诺什么）。

### 那些话怎么写

- **新开一份编码标准文件**（放在 `docs/agents/` 下，与 issue-tracker / triage-labels /
  queue-conventions / domain 并列），`CLAUDE.md` 加一行指路。**第一条**：用户可见的字符串不受
  列宽约束，一律不折行；**禁止用续行符去折印给用户的话**（那正是两次事故的成因）。规矩要连
  **验收方式**一起写下来：一条排掉注释行的 grep。
- `probe` 那处 13 个字面空格顺手收掉。**它不算路过** —— 本 spec 点名要立这条规矩，而它是这条
  规矩今天唯一的活口（`docs/agents/queue-conventions.md` 第 2 条）。

### 票与边

- **依赖已经量出来**：改名那一块要动一行 Device 成品那处文档，而搬家那一块要把那一段整个搬走
  —— **两者会撞**；改名与暂停那句话同在取数那个模块，**也得串**。`probe` 与规矩那一块与其余
  **一个文件都不相交**，全程可并行。
- **排法照老规矩：搬家先。** 搬家的 diff 是纯移动，内容改动落在它之后 —— 上一趟就是这么排的。

## Testing Decisions

好的测试只测外部行为，不测私有函数 —— 这个仓库靠集成测试让编译器来守这一条（第 1 趟 `/settle`
的 Q3）。

**接缝净变化是零：开一道、关一道。**

- **现成的两道直接用**：取数那一步（假枚举 + 假 Transport）承接改名与暂停那句话；一行的排版与
  那几行的合成搬模块之后**还是同两道缝**，那 26 条用例原样跑，只是 `use` 的路径变了。
  **搬家那一块不许改任何一条断言** —— 改了断言就说明它夹带了行为。
- **新开一道：整屏。** 它是不碰真系统所能够到的最高点（再往上是 `run`，那道墙躲不开真 HID 枚举）。
  它一次盖住四样今天测不到的东西，每样至少一条：进程枚举失败时按"没在跑"走并交出一句告警；
  空配置那一行、且未登记名单照旧出现；未登记那一段的标题与缩进；选出了 Primary 才记 / 选不出来
  什么都不动。
- **关掉一道**：`unregistered_ble_lines` 收私有，它那几条用例改从整屏驱动。
- **`probe` 那处不开接缝**：那句 `bail!` 今天没有任何用例断言（已核实），验收就是那条 grep 本身。
  给它补一条用例等于钉死一句没人钉的错误文案。
- **prior art**：假件全是现成的 —— 公共那份里的假枚举、"当下"、缺省 general、几个设备构造器、
  扫到的 BLE、在跑的上位机；而排版那批用例今天本来就走真的取数那一步去拿一份读数（不手搓
  原料），整屏那几条照这个路子写。
- gate 三条（`fmt --check`、`clippy --all-targets -D warnings`、`test`）全绿。

## Out of Scope

### `render` 那五个参数不捆

`(reading, staleness, provenance)` 一路同行，本趟又涨到五个参数。`RowReading` 已经装着五个里的
三个，把陈旧度也放进去就能收到两个参数 —— **这不是猜托盘要什么，是用一个已经在手的类型**。
**不做的理由不是形状难定，是它会挤进搬家那张票**：搬家票的证据价值全压在"diff 是纯移动"上，
掺一处签名重构进去，合并时就得逐行去比。这一条从第 1 趟的交接文件一路带到现在，**它还活着**，
下一个动这一层的人该接。

### 其余

- **`run` 本身仍然测不到**，那道墙这一趟不拆 —— 它要真去枚举本机 HID。壳里剩下的两处 fail-open
  （读状态文件失败当作没有历史值、写盘失败只在 stderr 说一句）**因此仍然没有用例**，它们碰的是
  真文件系统。
- **不加取数失败的分类枚举**（`docs/adr/0004`）。
- **除第 7、8 条用户故事点名的两处，用户可见的输出一个字不变。** 搬家那一块尤其：零输出变化。
- 陈旧标注的档位与阈值、来源那一段的措辞、暂停标注的其余部分。
- 托盘的"标灰"、键盘充电位的复测、以及 `docs/gaps.md` 里其余各条。
- 不再往下动取数那个模块的内部划分。

## Further Notes

**词汇先行，而且这次先行了一整趟。** 「取数失败」在磨这份 spec 的过程中一落定就写进了
`CONTEXT.md`，_Avoid_ 同时点名暂停（那是我们主动没去问）与失联（它只是三种来路之一）。
改名与两处文档改口留给票 —— 词汇表不必等代码。

**Q69 原本以为要靠"藏起来"证明接缝存在，结论相反。** 它记的是"那几个 `pub` 仍然是为了测试"，
而磨下来发现：接缝是那个整屏函数，**不是 `pub` 的数量**。把 `render` 藏起来换一个"只有一个入口"
的门面，代价是把仓库里行为最密的那一格（电量／来源／陈旧／暂停／充电态的组合）压进一个要整套
假设备栈才跑得起来的入口 —— 那是更差的用例，不是更硬的接缝。所以公开面几乎不变，变的是**它的
理由**，以及 `run` 之下终于有了一个测得到的顶。

**Q88 从一个字符变成了本仓库的第一条成文编码标准。** 磨的过程里查出来 `/code-review` 的
Standards 轴至今只跑在通用气味基线上 —— 而那份技能明写着"仓库的成文标准永远压过基线"。
一处一个字符的修正因此顺带补上了一个一直空着的位置。

**名字**：叫 `screen-as-a-function`，因为最大的那一块建的就是这个 —— 这一屏成为一个可测的函数；
其余三块是同一层的配套（它叫什么、它说什么、它的话怎么写）。名字说的是它建了什么，不是它从哪个
抽屉来的。
