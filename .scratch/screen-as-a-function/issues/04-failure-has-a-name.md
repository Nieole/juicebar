# 04: 取数失败有了名字，那个变体不再自称失联

**What to build:** 读代码的人不再在一个叫**失联**的变体里撞见**读取异常**——而词汇表恰恰明写着
不许这么指（「读取异常」那一条的 _Avoid_：那是去问了、问不到，而这里设备答了话）。

今天那个变体叫 `Lost`／失联，装着三种东西：试过了都失败（**包括答了坏帧**）、一条都不在场、
一条都没配。`CONTEXT.md` 里已经有了它们的上一层——**取数失败**（这一趟交不出可以印的数字，
而且不是因为我们没去问）。本票让代码跟上那个词。

顺带收掉两处将就：Primary 选择里那份候选读数、一行 Device 成品里那个候选，两处文档今天都拿
"失联"当上位词使，**因为过去没有别的词可用**。

用户看得见的输出**一个字不变**：那一行的措辞由失联原因那个函数给出，本票不碰它。

**Blocked by:** 01（呈现搬进自己的模块）—— 本票要改一行 Device 成品那处文档，而票 01 要把那一段
整个搬走。这条边买的是"两张票不在同一行上撞"，代价只是多等一轮。

**Status:** ready-for-agent

- [ ] 那个变体改名成一个**不宣称失联**的中性名（推荐 `Failed`）。它与暂停那个变体从此切成一条
      干净的二分：**取数失败** 对 **主动让开**
- [ ] **payload 不动**——不加取数失败的分类枚举（`docs/adr/0004` 否掉的正是它，而外层措辞要的
      那个区分，失联原因那个函数的三条分支已经免费给了）
- [ ] 两处文档改口：**Primary 选择里那份候选读数**的 `None`、**一行 Device 成品里那个候选**的
      `None`，今天都写着"失联"，改成"取数失败"
- [ ] 同文件里那几段提到这个变体的文档跟着改准，包括它自己那句「都试过了里也包括答了坏帧那一种」
- [ ] **本票不改 `CONTEXT.md`**：「取数失败」那一条已经在里面了（词汇先行）。若发现词条与代码
      对不上，那是词条的问题，**记下来别顺手改**——那是共享地盘
- [ ] **用户可见的输出一个字不变**
- [ ] **一条断言都不用改**：已核实用例里一次都没提这个变体名。若发现要改断言，先停下来想一想，
      那多半说明这一票夹带了行为
