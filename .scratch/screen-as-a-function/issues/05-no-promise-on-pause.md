# 05: 暂停那一行不再许一个它兑现不了的诺

**What to build:** 接收器插着、而设备本体关了机的那一趟，程序不再对用户说「关掉它就会恢复」。

那一支今天这么走：厂商上位机在跑 → Dongle24G 在场、被让开 → 没有别的 Endpoint 试过 →
原因列表为空 → 那一行末尾接上「，关掉它就会恢复」。而**列表为空只说明这一趟什么都没试过**，
不说明试了就会答话。接收器有**自己一组 VID/PID**（`docs/adr/0001`），所以设备关着机它照样被
枚举成在场；关掉上位机之后那条通路仍旧超时。

**这与上一趟要治的病同形**：那一行断言它不知道的事。上一趟核过的是这一支的**尾句**（原因列表
非空那一种），**没核这半句**——它不必等第四种 Endpoint，今天就在说。

改法是把那句关于未来的承诺**降格成条件句**：说我们会做什么，不说设备会怎样。用户唯一能据以
行动的东西（关掉那个上位机）一个字不丢。

**Blocked by:** 04（取数失败有了名字）—— 两张都在取数那个模块里，串行落地。票 04 先动结构，
本票落在它的最终形状上。

**Status:** ready-for-agent

- [ ] 原因列表**为空**那一支的后半句改成「，关掉它之后这几条才试得到」
- [ ] 原因列表**非空**那一支（「；剩下的也没读到 —— {原因}」）**一个字不动**：它本来就不承诺什么
- [ ] 那一行**仍然点名那个上位机、仍然说清哪几条被让开**：措辞变准不等于行动指引变少
- [ ] 一条新用例：厂商上位机在跑、Dongle24G 在场被让开、没有别的 Endpoint 顶上（原因列表为空）
      → 那一行**不含**任何关于"关掉之后就能读到"的断言，只说"关掉之后才试得到"
- [ ] **现有那条否定断言要跟着改**：取数那份用例里有一条断言那一行**不含**「关掉它就会恢复」
      （守的是"蓝牙地址写错时别许假承诺"）。本票之后这个字面量在仓库里**不再存在**，那条断言
      就永远不会失败了——把它改成断言新的那句措辞，否则它是一条钉着幽灵的死用例
- [ ] 那个变体上「它空不空改变这一行的措辞」那段文档跟着改准
- [ ] 除这半句，用户可见的输出一个字不变
