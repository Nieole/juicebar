# Parking lot：实现过程中取过的岔路

**Status:** 长期文件 —— 本仓库每一趟队列、每一张票共用这一份
**Opened:** 2026-09-09

## 这个文件是什么

实现票据时总会撞上票没预料到、或者票写错了的地方。**其中几乎没有一件该让队列停下来。**
它们落在这里：**走最站得住脚的那条路，把岔路记下来，继续走，等条件合适时再结算。**

它不是项目的长期缺口清单。长期缺口讲的是**产品**上缺什么，由下一个动这块产品的人来读；
这份文件记的是**执行中的岔路**——票写错了、spec 没说、两份文档互相打架——由决策者在坐下来
结算一批时来读。长期缺口永远不清空，这份文件由 `/settle` 成批结算，**绝不在队列收尾时结算**。

### 什么样的事配一条记录

一条记录是**你取过的一条岔路**，不是你做过的活。三条测试，全过才写：

1. **另一条路也站得住。** 你能把它写下来，而且它不是稻草人。
   只有一条路站得住，那就没有岔路——你做的事属于 commit message，不属于这里。
2. **翻案的代价关在这张票里。** 决策者以后改主意，代价是改一处，不是把已落地的活拆掉。
   如果翻案要伸到这张票外面，那是**停线**，不是记录。
3. **你能给出推荐。** 路是你走的，你有上下文说哪条该留下。
   一条交出去只有耸肩的记录，等于把你的上下文一起弄丢了——而推迟结算的全部意义，
   就在于这批东西真被读到时结算起来很便宜。

一份把票碰过的每件事都记下来的文件是日记，决策者会像读任何人的日记一样读它：根本不读。

### 停线 —— 只有这三种

停线很贵：决策者得把整个上下文重新装回脑子。门槛：

1. **继续走会写下一个错的产物，而撤销它要伸到这张票外面。**
   典型：票的指示与上游一个仍然有效的决定相抵触。
2. **动作不可逆，而且不止一个方向站得住。**
   典型：删除或重命名一个被多处引用的东西——一个 id、一个字段、一个文件。
3. **前提不存在，票根本没法开工。** 典型："在 X 之上建 Y"，而 X 并不存在。

其余凡是过了上面三条测试的：记下来，走最站得住脚的路，继续。这包括票里的数字与你实测的
对不上、验收条件读起来含糊、票没想到的第三种情况、以及你路过的一个不相干的缺陷。

### 编号

**整份文件一条序列**，这样一条记录在做出它的 commit 里、引用它的票里、多年后结算它的那一批里
是同一个名字。一条序列碰上并行的 agent 就会撞号，所以编排者把它切成**块**：每份 brief 拿到
一小段只属于它的号。没人需要向谁要号。某个块没被用完，编号上留个空档，不花什么代价。

号里不带票号，所以 **`From:` 是必填字段**——它是唯一说明哪张票发现了这条岔路的东西。

### Q120 —— 暂停而且从没读到过：设计稿没画过这个组合，图标上画"没有读数时"那个符号

**From:** resident-tray 票 01（图标渲染器按设计稿把图标画成位图）

**取的路**：`render` 的输入是图标状态与电量两样（票面、spec 都这么写），于是"有数的状态却没给
电量"是一个调得出来的组合。按 `CONTEXT.md` 的优先顺序，正常 / 低电 / 充电中 / Stale 都意味着手上
有数；走得到这里的正路只有一条——**暂停，而且从没取到过 Reading、也没有上次已知值**（暂停压过
无已知值，而"暂停期间显示上次已知值"这时无值可显示）。设计稿里的暂停永远带着预览电量 57，从没
画过这种情况。这里画"一次读数都没有过时画什么"那个符号（缺省 `--`），与无已知值一模一样；
`gray = "split_pause"` 时照样点上琥珀点。用例
`a_pause_with_no_known_value_draws_the_no_value_symbol_and_keeps_its_dot` 钉住它，期望值取自设计稿
无已知值那一张、加上暂停那一张的琥珀点。

**另一条路**：照设计稿渲染器**字面上**会画出的样子——它的 `levelText(null)` 得到字符串 `"null"`，
字形表里一个字都查不到，于是数字那一块留空：D 里只剩空的轨道，A 纯数字里整个图标是空的。理由是
"像素的唯一真相是设计稿"，一个像素都不自己发明。

**推荐**：留现在这条。设计稿画空白不是一个决定，是 `String(null)` 的意外；A 纯数字下一个全空的
图标会被读成"程序坏了"，而 `CONTEXT.md` 写暂停时特意要避免的正是这种印象。代价是缺省
`gray = "split"` 下它与无已知值长得一样——可两者说的本来都是"手上没有数"，想分开的用户有
`split_pause`。翻案面是 `src/icon/mod.rs` 里 `middle` 的一个分支加一条用例。归决策者拍板。

### Q121 —— 175% 缩放正好落在 24 与 32 中间，取了小的那一档

**From:** resident-tray 票 01（图标渲染器按设计稿把图标画成位图）

**取的路**：`IconSize::for_dpi` 照设计稿的 `autoSize()`：目标 16 × 缩放，取四档里最近的，平手取小的。
175%（目标 28）因此用 24 像素那一档，112.5% 用 16，137.5% 用 20。平手规则设计稿没写成一句话，是它
`reduce` 里那个严格小于号的结果。

**另一条路**：平手取大的。175% 是 14 英寸笔记本常见的缺省缩放，托盘在那里要的是 28 像素：24 放大到
28 与 32 缩小到 28 都会糊，但放大糊掉的是每一条笔画，像素字形上比缩小更显眼。

**推荐**：先照设计稿（取小的）。两条路都糊，没有一条是"对的"，而 ADR-0005 说像素以设计稿为准。
真要解决 175%，该做的是第五档 28 像素（设计稿里补一列、审过、再导基准），不是改平手规则。翻案面
是 `for_dpi` 里一个比较符号加用例里三行。归决策者；若要加 28 那一档，那是一张新票，设计稿先审。

### Q122 —— 系统字体按墨迹量、按墨迹居中、落在整像素上，没照设计稿的前进宽度与小数坐标

**From:** resident-tray 票 01（图标渲染器按设计稿把图标画成位图）

**取的路**：系统字体豁免逐像素，但"怎么放"仍照设计稿 `drawText` 的 `sys` 那一支：Segoe UI 粗体，
字号从方框高度 × 1.35 往下试到 6，第一个放得下的就用，都放不下就不画。两处没照抄：设计稿横向用
`measureText().width`（前进宽度，含字形两侧的留白）判断放不放得下、也按它居中，这里横竖都按墨迹的
外接矩形；设计稿把字画在小数坐标上，这里画在整像素上。

**另一条路**：连这两处也照设计稿——用 `GetTextExtentPoint32W` 量前进宽度、按它居中。理由是"照设计稿"
不该挑着照，而且豁免的只是像素，不是放法。

**推荐**：留墨迹。16 像素里差一个像素就看得出偏：数字 1 的前进宽度与 8 相同，按前进宽度居中的"1"
会明显偏左；票面要断言"居中"，也只能对墨迹断言。代价是同一字号下墨迹判断比前进宽度宽松一点，
偶尔会选大一号的字。翻案面在 `src/icon/system_font.rs` 一个函数里。归决策者，不急。

### Q123 —— 基准多导了一组电量扫描，它抓到了票面覆盖面碰不到的一处交叉

**From:** resident-tray 票 01（图标渲染器按设计稿把图标画成位图）

**取的路**：票面的覆盖面（缺省 8 状态 × 4 尺寸 × 2 调色；每项设置从缺省只改一项、每个取值一组）
之外，设计稿的导出还多导了 `tests/icon_baselines/levels.txt`：四个画法 × 正常与充电中 × 电量
0 / 1 / 50 / 99 / 100 × 四个尺寸，只取深色，160 张。票面那套里电量只有 57、12 和 100（后者只在 D
里），于是 C 圆环的最短一截与满圈、各画法的一位数居中、**C 圆环里的满格用状态色、别的画法用数字色**
这几处，一张基准都碰不到。最后那一处在 TDD 里只写被基准逼出来的代码时不会被逼出来——是这组扫描
加上充电中之后变红，才把它逼出来的。

**另一条路**：严格照票面的覆盖面，不多导。"不做全组合"的精神是别堆没有信息量的网格，多一组就多
一份要跟着设计稿重导、要有人看得懂的东西。

**推荐**：留着。160 张换来的是票面那套在结构上看不见的一类错误：只在"某个画法 × 某个电量 × 某个
带颜色的状态"交叉处才走的分支。它仍然不是全组合（没有沿设置那几维展开）。若决策者认为这是覆盖面
规则本身的漏洞，该改的是 spec Testing Decisions 里"图标渲染"那一条：在"每项只改一项"之外加一句
"每个画法走一遍电量的两头"。翻案面是 `levels.txt`、设计稿导出里的几行、一条用例。归决策者，
`/settle` 时看要不要升进 spec。
