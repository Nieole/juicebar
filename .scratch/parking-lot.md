# Parking lot：实现过程中取过的岔路

**Status:** 长期文件 —— 本仓库每一趟队列、每一张票共用这一份
**Opened:** 2026-09-09

## 这个文件是什么

实现票据时总会撞上票没预料到、或者票写错了的地方。**其中几乎没有一件该让队列停下来。**
它们落在这里：**走最站得住脚的那条路，把岔路记下来，继续走，等条件合适时再结算。**

它不是项目的长期缺口清单。长期缺口讲的是**产品**上缺什么，由下一个动这块产品的人来读；
这份文件记的是**执行中的岔路**——票写错了、spec 没说、两份文档互相打架——由决策者在坐下来
结算一批时来读。长期缺口永远不清空，这份文件由 `/settle` 成批结算，**绝不在队列收尾时结算**。

### 什么样的事配一条记录

一条记录是**你取过的一条岔路**，不是你做过的活。三条测试，全过才写：

1. **另一条路也站得住。** 你能把它写下来，而且它不是稻草人。
   只有一条路站得住，那就没有岔路——你做的事属于 commit message，不属于这里。
2. **翻案的代价关在这张票里。** 决策者以后改主意，代价是改一处，不是把已落地的活拆掉。
   如果翻案要伸到这张票外面，那是**停线**，不是记录。
3. **你能给出推荐。** 路是你走的，你有上下文说哪条该留下。
   一条交出去只有耸肩的记录，等于把你的上下文一起弄丢了——而推迟结算的全部意义，
   就在于这批东西真被读到时结算起来很便宜。

一份把票碰过的每件事都记下来的文件是日记，决策者会像读任何人的日记一样读它：根本不读。

### 停线 —— 只有这三种

停线很贵：决策者得把整个上下文重新装回脑子。门槛：

1. **继续走会写下一个错的产物，而撤销它要伸到这张票外面。**
   典型：票的指示与上游一个仍然有效的决定相抵触。
2. **动作不可逆，而且不止一个方向站得住。**
   典型：删除或重命名一个被多处引用的东西——一个 id、一个字段、一个文件。
3. **前提不存在，票根本没法开工。** 典型："在 X 之上建 Y"，而 X 并不存在。

其余凡是过了上面三条测试的：记下来，走最站得住脚的路，继续。这包括票里的数字与你实测的
对不上、验收条件读起来含糊、票没想到的第三种情况、以及你路过的一个不相干的缺陷。

### 编号

**整份文件一条序列**，这样一条记录在做出它的 commit 里、引用它的票里、多年后结算它的那一批里
是同一个名字。一条序列碰上并行的 agent 就会撞号，所以编排者把它切成**块**：每份 brief 拿到
一小段只属于它的号。没人需要向谁要号。某个块没被用完，编号上留个空档，不花什么代价。

号里不带票号，所以 **`From:` 是必填字段**——它是唯一说明哪张票发现了这条岔路的东西。

### Q58 —— 草稿里那句"表在 `src/config.rs` 的 `KNOWN_DEVICES`"指向一个本票删掉的路径

**From:** 票 01（配置模块拆成四个文件，公开面一个字不变）

**取的路**：原样留着，一个字没动。`NOTHING_RECOGNISED` 那段用户可见的文案里写着
"（表在 src/config.rs 的 KNOWN_DEVICES）"，而本票把 `src/config.rs` 拆成了 `src/config/`，
那张表现在住在 `src/config/known_devices.rs`。这句话于是指向一个不存在的文件。

**另一条路**：顺手把它改成 `src/config/known_devices.rs`。**没有任何东西挡着这一改**：
全仓库只有两处提到 `src/config.rs`，一处是这个常量，另一处是 `tests/config.rs` 第 3 行
（本票已经在改那一行），而**没有一条用例断言这段文案、也没有一条断言这个路径**——改它的
代价就是这一个字符串。

**推荐**：本票留原样，这个修正归票 03。理由不是"改不动"，而是**这张票作为证据的全部价值
都压在"草稿文本逐字节不变"这一句上**：合并时靠它一眼就能核完，一处文案改动就得逐字去比。
为一处在任何地方都值得做的路径修正换掉这个判据，是笔坏交易。而它不必等结算——票 03
（草稿里的蓝牙占位退掉硬写常量）本来就在动草稿生成，这个修正在那里搭车，对本票的证据
零代价。**但票 03 必须真的收掉它**：搬家之前那个路径是对的，是这次拆分让它变成假话，
所以它不是一处路过的旧疤，而是本票制造、只差最后一步的缺陷。

### Q59 —— 三个叶子函数的调用方跨文件，票面那两条规则因此不能同时成立

**From:** 票 01（配置模块拆成四个文件，公开面一个字不变）

**取的路**：按主题归组。`endpoint_block` 留在 `draft.rs`（`edit.rs` 借它），
`is_present` 与 `same_scanned_identity` 进 `known_devices.rs`——后两个在本文件里
一个调用方都没有，调用方全在 `draft` / `edit`。归组的依据是"一个 Endpoint 块长什么样"
只该有一个写法，以及那两个谓词都只比对身份。

**另一条路**：`endpoint_block` 提到 `mod.rs`（两侧都借的中立位置），
`same_scanned_identity` 按票面字面跟去它唯一的调用方 `edit.rs`。

**这是真岔路，因为票面两条规则在这里互斥**：「四个文件各只有一个改动理由」与
「叶子辅助函数跟着它们的调用方走」。`endpoint_block` 两侧都有调用方，跟谁走都会让那个
文件多一个改动理由；留在原处，则"改一句草稿文案只动一个文件"不完全成立——改这个渲染函数
会同时改草稿和 `config-refresh` 补出来的块。两条 review 轴各自独立指到了同一处：
Standards 轴记成"可能的 Feature Envy"，Spec 轴记成"`draft.rs` 有两个改动理由"，
两轴都不建议阻塞。

**推荐**：维持现状。`endpoint_block` 的共享**不是耦合失误，而是一条被文档明写的不变式**
——"草稿写下的块与 `config-refresh` 补出来的块逐字一致"，`insert_endpoint_block` 的
文档头正是为这件事写的；把它提到 `mod.rs` 只是把一个纯文案渲染函数塞进 schema 文件，
换来的仅仅是规则的字面好看一点。翻案的代价是移一个函数加一行 `use`，关在本票里。
真要消掉这条张力，该改的是票面那句规则的措辞（多调用方的叶子按主题归组），不是代码。

### Q68 —— 既断言原料、又断言那一行的用例，分文件时归哪一半

**From:** 票 02（取数搬进自己的模块，`pub` 不再是"为了测试"）

**取的路**：**看它断言什么，不看它调用什么。**断言排好版的那一行（走 `status::render`）的
留在 `tests/status.rs`；只断言取数交出来的东西（`EndpointReading` / `NoReading` /
`RowReading`，以及假枚举的 `opens()` / `ble_reads()` / `sent()`）的进 `tests/readout.rs`。
暂停那一段因此被切开：`yields_the_two_hid_endpoints_without_opening_them_at_all` 那三条进
取数那边，`keeps_the_last_known_value_while_paused_and_says_which_it_is` 那三条留在原处。
排版那半边照旧调 `readout::read` 去拿一份真读数——那不是越界，是不手搓 `EndpointReading`。

**另一条路**：按原文件的分节走。那一节的分隔注释原话是"这里断言的是**取数那一步怎么让开**"，
六条本来是一组；照它把六条整组搬进 `tests/readout.rs`，让那个文件也留一个 `line_of_row`
去调 `status::render`。**这不是稻草人**——分节注释是原作者的分类，比我这条规则更有出处。

**这是真岔路，因为那三条用例两边都真的断言了**：既断言 `readout.provenance` 与
`opens().is_empty()`，又断言那一行里的"已暂停（VGN VHUB.exe 正在运行）"。一条断言都不许改，
所以每条只能整条去一边，没有第三种走法。

**顺带量到 spec 自己的算术对不上**：Testing Decisions 写着"取数那一半（**26 处取数调用** +
8 处退到历史值 + 失败枚举与原料结构）搬进新的取数用例文件"，而票面同时要求"排版与那几行的
合成留在原处"。实测那 26 处 `read` 调用里**有 9 处长在排版用例里**（它们调 `read` 只是为了
拿一份真读数，断言的是排好版的那一行），所以"26 处全搬"与"排版留在原处"**不能同时成立**：
最终 17 处搬走、9 处留下（`read_or_last_known` 那 8 处里 5 处搬走、3 处留下）。这与票 01
量到的 Q59 是同一个形状——票面两条规则在某个具体对象上互斥，而不是实现走错了。

**推荐**：维持现状。取数那个用例文件**一次都不提 `cli::status`**（实测：`status::` 在
`tests/readout.rs` 里出现 0 次），这件事本身就是这次搬家最硬的证据——它证明取数那一半确实
不依赖排版。另一条路会让新文件第一天就借回 `status::render`，那道缝在用例上就先糊了一半。
翻案的代价是三条用例挪个文件加一个 helper，关在本票里。

### Q69 —— `render` 那半边的 `pub` 仍然是"为了测试"，而本票结构上修不到它

**From:** 票 02（取数搬进自己的模块，`pub` 不再是"为了测试"）

**取的路**：只把 `read` / `read_or_last_known` 那两处的理由改成"它是这个模块的接口"，
`cli::status` 剩下那几个 `pub` 的文档一个字没动，只按机械适配把 [`read`] 的链接目标补成
`crate::readout::read`。

**另一条路**：把 `render` 与 `unregistered_ble_lines` 上那句"`pub` 与 [`read`] 同理"
一起改掉——`read` 那一处的理由已经变了，这句"同理"现在指向一个不再成立的对照。
**这不是稻草人**：这句话是被本票改成假话的，与 `src/state.rs` 那处路径同一类。

**这是真岔路，也是本票范围的边界**：spec 的 Problem Statement 点的是"`read` **与**
`render` 的 `pub` 是为了测试"，而 Out of Scope 又写着"不再往下拆 `cli::status` 剩下的
那约 440 行"。搬家只修得到 `read` 那一半。实测：`render` / `primary_lines` /
`unregistered_ble_lines` / `DeviceRow` 在 `src/` 里**一个非测试调用方都没有**，`main.rs`
只调 `run`。它们 `pub` 的唯一理由就是 `run` 测不到（它要真去枚举本机 HID，parking lot
Q13 记着这一截），所以只要 `run` 还是那道躲不开真系统的墙，这几个 `pub` 就永远是
"为了测试"——**搬到哪儿都一样，这不是位置问题**。

**推荐**：本票维持现状，不改那两句。改它只有两种写法，都更差：照实说"`pub` 是为了能断言到
这一行"，等于把 spec 称为症状的那句话重新刻回去；或者编一个"它是某个模块的接口"，而那个
模块今天还不存在。这条真正的归宿是**给呈现那一半也划一道缝**（那时 `render` 的 `pub` 自然
变成那道缝的接口），而那是另一张票的活。翻案的代价是两句 doc，关在本票里。
