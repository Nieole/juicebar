# Parking lot：实现过程中取过的岔路

**Status:** 长期文件 —— 本仓库每一趟队列、每一张票共用这一份
**Opened:** 2026-09-09

## 这个文件是什么

实现票据时总会撞上票没预料到、或者票写错了的地方。**其中几乎没有一件该让队列停下来。**
它们落在这里：**走最站得住脚的那条路，把岔路记下来，继续走，等条件合适时再结算。**

它不是项目的长期缺口清单。长期缺口讲的是**产品**上缺什么，由下一个动这块产品的人来读；
这份文件记的是**执行中的岔路**——票写错了、spec 没说、两份文档互相打架——由决策者在坐下来
结算一批时来读。长期缺口永远不清空，这份文件由 `/settle` 成批结算，**绝不在队列收尾时结算**。

### 什么样的事配一条记录

一条记录是**你取过的一条岔路**，不是你做过的活。三条测试，全过才写：

1. **另一条路也站得住。** 你能把它写下来，而且它不是稻草人。
   只有一条路站得住，那就没有岔路——你做的事属于 commit message，不属于这里。
2. **翻案的代价关在这张票里。** 决策者以后改主意，代价是改一处，不是把已落地的活拆掉。
   如果翻案要伸到这张票外面，那是**停线**，不是记录。
3. **你能给出推荐。** 路是你走的，你有上下文说哪条该留下。
   一条交出去只有耸肩的记录，等于把你的上下文一起弄丢了——而推迟结算的全部意义，
   就在于这批东西真被读到时结算起来很便宜。

一份把票碰过的每件事都记下来的文件是日记，决策者会像读任何人的日记一样读它：根本不读。

### 停线 —— 只有这三种

停线很贵：决策者得把整个上下文重新装回脑子。门槛：

1. **继续走会写下一个错的产物，而撤销它要伸到这张票外面。**
   典型：票的指示与上游一个仍然有效的决定相抵触。
2. **动作不可逆，而且不止一个方向站得住。**
   典型：删除或重命名一个被多处引用的东西——一个 id、一个字段、一个文件。
3. **前提不存在，票根本没法开工。** 典型："在 X 之上建 Y"，而 X 并不存在。

其余凡是过了上面三条测试的：记下来，走最站得住脚的路，继续。这包括票里的数字与你实测的
对不上、验收条件读起来含糊、票没想到的第三种情况、以及你路过的一个不相干的缺陷。

### 编号

**整份文件一条序列**，这样一条记录在做出它的 commit 里、引用它的票里、多年后结算它的那一批里
是同一个名字。一条序列碰上并行的 agent 就会撞号，所以编排者把它切成**块**：每份 brief 拿到
一小段只属于它的号。没人需要向谁要号。某个块没被用完，编号上留个空档，不花什么代价。

号里不带票号，所以 **`From:` 是必填字段**——它是唯一说明哪张票发现了这条岔路的东西。

### Q100 —— 两处候选的 `None` 没照票面写成"取数失败"：暂停也落在那里

**From:** screen-as-a-function 票 04（取数失败有了名字）

**取的路**：两处都写成"取数失败或者暂停，又退不到上次已知值"（`src/primary.rs` 那份
候选读数、`src/cli/status.rs` 一行 Device 成品那个候选）。票面要的是"改成取数失败"，而这两个
`None` 的真实来路比它宽：`status::run` 里 `Err(no_reading) => (…, None)` 那一支不分变体，
暂停又撞上没有上次已知值（一台从没读到过的设备，第一次运行时厂商上位机就开着）同样落成
`None`——同一个文件里"失联与暂停在这里合成一支"那句注释说的就是这件事。只写"取数失败"，
等于拿取数失败说暂停，而那是「取数失败」这一条 _Avoid_ 点名的第一件事。后半句同理：有历史
值时两种下场都退成一份 Stale 的读数，`None` 只在退不到时才出现。

**另一条路**：照票面逐字写"`None` = 取数失败"；或者更进一步，一个领域词都不用，只写"这一轮
手上没有读数"——`primary` 模块自称只收"已经定下来的结论"，本来不必知道没数是因为什么。后者
同样不撒谎。

**推荐**：维持现在的写法。这两处文档存在的理由就是告诉读的人 `None` 从哪儿来，而本票的全部
理由是"词汇表、类型名、文档三处说同一件事"——少说一个暂停，文档就又比代码窄了一回，与本票
要治的病同形。翻案的代价是两行文档。归 `/settle` 拍板。

### Q103 —— 「上次已知值」说"设备失联时拿它顶上"，代码与 ADR 0004 对每一种取数失败都这么做

**From:** screen-as-a-function 票 04（取数失败有了名字）

**取的路**：`CONTEXT.md` 不动（票面明令：词条对不上是词条的问题，记下来别顺手改），代码里跟着
这个词条说话的几处也不动：`src/readout.rs` 里 `read_or_last_known` 文档那两句（"'失联'与'没有
已知值'是两回事"、"失联时拿出上次已知值"）、`src/state.rs` 的 `Provenance` 文档（"同一份读数
在设备失联之后拿出来就不是现状了"）与它的 `LastKnown` 变体（"设备这一趟失联"）、
`src/cli/status.rs` 里 `stale_marker` 文档那句"一份失联后从磁盘上捞出来的读数"。

**对不上的地方**：`read_or_last_known` 在 `read` 交出任何一种 `NoReading` 时都去拿历史值，读取

**推荐**：先改词条——「上次已知值」那句改成"设备取数失败或者暂停时拿它顶上"之类，归用户经
`/domain-modeling` 拍板；代码那几处随后一次跟上，其中 `readout.rs` 与 `state.rs` 那两句里本来
就有"这一趟"，resident-tray 票 03 反正要逐句改写它们。

### Q110 —— 验收 grep 扫全部 `.rs`，不照票面只扫 `src` 与 `tests`

**From:** screen-as-a-function 票 02（用户可见的长句怎么写，成文）

**取的路**：规矩里写下的验收是 `git grep --untracked -nE '\S {5,}\S' -- '*.rs' | grep -vE
'^\S+:[0-9]+: *//'`——按 `*.rs` 过滤，不列目录。票面那一格「那条 grep 在 `src` 与 `tests` 上归零」
照样成立：全部 `.rs` 是它的超集，今天两边都是零（`src` `tests` 之外也还没有 `.rs`）。理由是 rt-02
马上要把 `src/cli/probe.rs` 整个搬去 `examples/`：一条只扫 `src tests` 的验收，在搬家那天就静静地
看不见本票修的那一行，而且不会有任何东西红。换成 `git grep` 还顺带两件事：被 gitignore 的 `target/`
天然不扫；`--untracked` 让还没 `git add` 的新文件也在视野里——否则写完新文件就跑验收，会绿着回答
一棵漏了文件的树。

**另一条路**：照票面与交接文件（`.scratch/homeless-2.md`）的原话，`grep -rnE '\S {5,}\S'
--include=*.rs src tests | grep -vE …`。**这不是稻草人**：它是票面的字面、是实测过的那条命令；
而且可以论证 `examples/` 下是开发者自己跑的探针，不是产品输出，本来就该在规矩外面。

**推荐**：维持全部 `.rs`。`probe` 搬进 `examples/` 之后，它那句话仍然印到一个人眼前，事故的样子
也一模一样；规矩管的是"印给人看的话"，不是哪个目录。翻案的代价是规矩文件里那一行命令，关在本票里。
归 `/settle` 拍板；rt-02 落地时在它的树上把这条命令原样跑一次即可顺带核掉（应当仍是零）。

### Q111 —— 规矩立下时还有六句用户可见的话用续行符折着，而票面说 `probe` 是唯一的反例

**From:** screen-as-a-function 票 02（用户可见的长句怎么写，成文）

**取的路**：一个字没动，只在规矩里点名、在这里记位置。票面与 spec 都说 `probe` 那处是这条规矩
"今天唯一的反例"——这只对**事故**成立（那条 grep 今天只命中它），对**规矩**不成立。规矩本身
（票面原话）是「禁止用续行符去折印给用户的话」，而按行尾的 `\` 扫、排掉多行块（见 Q112），
`src/` 里还有六句单行的用户可见文案是这么折的：

- `src/config/edit.rs:82`、`:97`、`:114`（`config-refresh` 的三句提醒）
- `src/endpoints.rs:405`（BLE 地址找不到时的错误）
- `src/sources/vgn_keyboard.rs:88`、`src/sources/vgn_mouse.rs:68`（两句读取异常的文案）

复现：`git grep -nE '[\\]$' -- 'src/*.rs' | grep -vE '[\\]n *[\\]$|"[\\]$'` 出七行，去掉
`src/config/draft.rs:28`（`endpoint_block` 那个多行块的第一行）就是这六句。把范围放到 `'*.rs'`
还会多出 `tests/config.rs:430` 那句 `assert!` 文案，它也是这么折的；规矩把测试断言划在"用户可见"
外面（它只在测试红的时候印给改代码的人看），所以它不算第七句。

**`edit.rs:114` 正是第一次事故的现场**：Q79 那处 22 个空格，`d42d004` 的修法是把 `\` 补回去——
病灶原样放回了原处。六处的 `\` 今天都在、印得都对，所以 grep 是零、每一格都勾得上；但每一处都只差
一个字符就是第三次事故，而那条 grep 只看得见"续行符连同换行一起没了"那一种形状，"续行符没了、换行
还在"那一种它看不见。

**另一条路**：在本票里一起展开成一行。**这不是稻草人**：六处都是纯机械的改动，展开前后输出**逐字节
相同**（续行符吃掉的正是换行和缩进），没有任何用例要动；而且规矩就是这么要求的。不取它，是因为票面
那一格「除那一处，不动任何别的字符串」——它的立意（本票的 diff 越窄越好核）在这里也站得住：多出来的
六处落在三个模块里，与 `probe`、与规矩文件都不相干。

**推荐**：展开，但不在本票。它**无主**——这一趟队列里没有哪张票碰 `src/config/edit.rs`、
`src/endpoints.rs` 或 `src/sources/`——按 queue-conventions 第 2 条的推论，它正是该被 `/settle`
结算的形状：一张很小的票（六处展开、输出逐字节不变、验收是那条复现命令归零），或者搭下一张碰这几个
文件的票的车。规矩里已经写了"谁改到其中哪一句，就把那一句展开"，所以不结算也不会恶化，只是不会自己
消失。翻案的代价是展开那六句、删掉规矩里点名它们的那一段，关在一处。

### Q112 —— 多行块里的续行符不归这条规矩管

**From:** screen-as-a-function 票 02（用户可见的长句怎么写，成文）

**取的路**：规矩只管"一句话"——输出里本来是一行的文字；源码断点都落在输出换行处的多行块划在
外面（断点前若有几格空白，那是下一行要印出去的缩进）。具体是 `src/config/draft.rs` 里 `endpoint_block` 那种 `\n  \` 的 TOML 块、几段 `"\` 起头的
常量、`remedy` / `provenance` 那几段按草稿行宽折好的注释散文（`\n\`），加上
`src/config/known_devices.rs:136` 那一处，约十个字符串。依据是 Q90 已经写下的判断（"它们是有意的
多行块，与一行散文不同类"），以及这条规矩的解法——"写成一行"——对一段本来就要印成好几行的文字
用不上。

**另一条路**：连多行块一起管，续行符在任何用户可见的字符串里都不许出现，多行块改成一行一个字面量
（`concat!` 按输出行分段、逐行 `writeln!`，或者像 `known_devices.rs:136` 那样把续写的一行顶格写，
丢了 `\` 也漏不出空白）。**这不是稻草人**：规矩的"为什么"对它们一字不差地成立——`draft.rs:397`
那句的 `\` 一丢，草稿里就多出一个空注释行，下一行 `#` 后面跟着 18 个空格——而那条 grep 同样看不见
这一种。

**推荐**：维持划在外面。两次事故都是单行散文，多行块至今没出过事；为它另立写法是在没有证据的地方
立法，而且会让这条规矩从第一天起就多出约十处例外。真到多行块也出事的那天，该立的是另一条规矩（多行
的用户可见文字怎么写），不是把这一条撑大。翻案的代价是规矩里"边界"那一段，关在本票里；归 `/settle`
拍板。

### Q120 —— 暂停而且从没读到过：设计稿没画过这个组合，图标上画"没有读数时"那个符号

**From:** resident-tray 票 01（图标渲染器按设计稿把图标画成位图）

**取的路**：`render` 的输入是图标状态与电量两样（票面、spec 都这么写），于是"有数的状态却没给
电量"是一个调得出来的组合。按 `CONTEXT.md` 的优先顺序，正常 / 低电 / 充电中 / Stale 都意味着手上
有数；走得到这里的正路只有一条——**暂停，而且从没取到过 Reading、也没有上次已知值**（暂停压过
无已知值，而"暂停期间显示上次已知值"这时无值可显示）。设计稿里的暂停永远带着预览电量 57，从没
画过这种情况。这里画"一次读数都没有过时画什么"那个符号（缺省 `--`），与无已知值一模一样；
`gray = "split_pause"` 时照样点上琥珀点。用例
`a_pause_with_no_known_value_draws_the_no_value_symbol_and_keeps_its_dot` 钉住它，期望值取自设计稿
无已知值那一张、加上暂停那一张的琥珀点。

**另一条路**：照设计稿渲染器**字面上**会画出的样子——它的 `levelText(null)` 得到字符串 `"null"`，
字形表里一个字都查不到，于是数字那一块留空：D 里只剩空的轨道，A 纯数字里整个图标是空的。理由是
"像素的唯一真相是设计稿"，一个像素都不自己发明。

**推荐**：留现在这条。设计稿画空白不是一个决定，是 `String(null)` 的意外；A 纯数字下一个全空的

### Q153 —— 无已知值只给"还没有一次取数有过结果"：第一次就失败画取数失败，还没取过数也不算暂停

**From:** resident-tray 票 03（"这一轮的结果"成形，低电阈值第一次生效）

**取的路**：`InHand::NoKnownValue`（→ 无已知值）只给"还没有一次取数有过结果、也没有上次已知值"；一次取数已经
失败、又退不到上次已知值的，一律取数失败——哪怕这台设备从来没读到过。

**另一条路**：照 `CONTEXT.md`「图标状态」那句"无已知值（从没取到过一份 Reading，也没有上次已知值）"的字面，
从没读到过的那台第一次失败也是无已知值。站得住：字面上两条都符合，而优先顺序把它们放在同一档（"取数失败 /
Unknown / 无已知值"），没说谁先。

**同一条边界的另一面**（review 提出）：`InHand::NoKnownValue` 不带暂停这一维，所以托盘刚启动、厂商上位机开着、
某台设备的第一次取数还没回来时，它画的是无已知值，不是暂停——而 `CONTEXT.md` 的顺序是"暂停 > … 无已知值"。
这里的取法是：暂停是一次取数的事（"我们主动不去打开"），还没取过数就还没有什么让开过；第一次取数一回来，
那一份就是 `NoReading::Paused`，图标随即变成暂停（用例 `a_paused_device_is_paused_whatever_else_it_has_in_hand`
里"无已知值"那一例就是这一种：从没读到过、也没有上次已知值、而且让开了）。另一条路是让这一轮在手上有一次
撞见了上位机的询问时，把还没取过数、配了 HID 的设备也画成暂停——免得启动时先闪一下"无已知值"，代价是这一层
要重做一遍"哪几条会让开"的判断（今天那只在取数那一层做，而且要看 Endpoint 在不在场）。

**推荐**：两面都维持。设计稿里取数失败与无已知值要用户做的事不同：取数失败是"插线、配对，或查权限"，无已知值是
"等第一次读到"——一台试过、失败了的设备，用户该看见的是前者；启动时那一闪由 rt-04 让第一轮取数尽快发出去就能
压到看不见。要定下来，是给 `CONTEXT.md`「图标状态」那一句补半句（"还没有一次取数有过结果"），归用户经
`/domain-modeling` 拍板；本票翻案的代价是 `icon_state` 里一个分支（暂停那一面还要多收一个参数）。

Primary Device 那一台在新的"当下"重判一次、重排悬停提示——Primary Device 不换人，图标不重判。于是一份当场读到的
`Ble` 缓存越过陈旧阈值的那一刻，图标要等下一次取数的结果才变灰（最多一个轮询间隔）。

**另一条路**：时钟每走一格都重开一轮（重判全部、重选 Primary Device、重画）。站得住：图标与悬停提示永远对着同一个
"当下"，越过阈值当场就变灰；代码更少（一条路径）。

**推荐**：维持——每秒一轮会让"一轮"失去 `CONTEXT.md` 给它的意思（"任一台有新结果就开始新的一轮"），而且每秒都可能
换 Primary Device、每秒都要问一次该不该存状态文件。那一个间隔的滞后，在每台都照节奏取数的托盘里看不出来。翻案的代价
是 `src/tray/round.rs` 的 `on_tick`。归 `/settle`。

### Q165 —— 日志：每一次取数失败都记，不去重；暂停不记

**From:** resident-tray 票 04（托盘：图标出现、悬停看得到、右键能退出）

**取的路**：票面"本票至少记下每次取数失败的完整原因"照字面：交不出数的、退到了上次已知值的（那一句本来被
`read_or_last_known` 咽掉了，本票给取数那一层加了 `read_or_last_known_with_reason` 把它交出来），每一次都写一行完整
错误链；暂停不写（`CONTEXT.md`：那不是失败，是我们主动没去问）。日志 1 MiB 滚一次，留上一份。

**另一条路**：只在变化时记——第一次失败记一行、恢复时记一行，中间同一个原因不重复。站得住：一台 2.4G 永远读不到的
键盘每分钟一行，一天一千多行，真正新鲜的那一次失败会被它淹掉、滚掉。

**推荐**：本票维持（票面字面）；日志真吵起来（票 05 各走各的节奏之后，`Ble` 十秒一次）就改成变化时记，改法关在
`src/tray/round.rs` 的 `log_failure`。归 `/settle`。

### Q166 —— Q154 在托盘里：两条用例绕着它写

**From:** resident-tray 票 04（托盘：图标出现、悬停看得到、右键能退出）

**取的路**：本票照 queue-conventions 没修 Q154（票面没点名）。它在托盘里确实成了常态：取数线程手上那一份状态里有这台

**另一条路**：本票顺手修掉 Q154（`candidate()` 在 `Provenance::LastKnown` 时交 `Stale`），两条用例改用真实形状。站得住：

### Q200 —— 低电通知只看来路：这一次取数真读到的就算，不问它多旧、为谁让开过

**From:** resident-tray 票 08（低电通知）

**取的路**：规则只分"这一次取数读到的"与"上次已知值"（`Provenance`）：前者低于阈值、又没提醒过，就提醒；后者既不提醒、也不
重新武装。于是一份陈旧的 `Ble` 缓存——哪怕过了 `very_stale_after`（缺省一天），悬停提示与图标都已不肯显示那个百分比
（Q161）——以及上位机在跑时 `Ble` 顶上来的那一份（图标上画暂停），都照样提醒，正文里写着那个百分比。理由：spec 只点名了
上次已知值这一种例外；`CONTEXT.md`「图标状态」里"低电压过 Stale"的理由（读不到新数的设备，最常见的原因就是没电了）在这里
一样成立；`DeviceState::assess` 上写着 VeryStale 那一档照样参与低电判定（Q151）。两条用例钉着它：
`an_old_ble_cache_below_the_threshold_still_reminds`、`a_reading_taken_while_the_vendor_hub_is_running_still_reminds`。

**另一条路**：过了 `very_stale_after` 的那一档当成上次已知值——不提醒、也不重新武装；或者照样提醒，但正文像悬停提示那样只说
"{日期} 的读数"，不写百分比。站得住：Q161 已经定了"十天前的一个 62 画在托盘上就是一句假话"，而通知成了整个托盘里唯一还会把
那个数说出来的地方；一台在抽屉里放了好几天的蓝牙键盘，托盘每启动一次就提醒一次。

**推荐**：维持。那一次提醒每次运行最多一次，它提醒的那件事（这台多半已经没电了）多半是真的。若嫌正文写出了一个旧百分比，改法
是 VeryStale 时正文换成日期那一句，关在 `src/tray/notify.rs` 的 `low_battery` 与上面那条用例。归 `/settle`。

### Q201 —— 低电通知的措辞：电量带着来源标注，正文写出阈值

**From:** resident-tray 票 08（低电通知）

**取的路**：标题"{名字} 电量低"，正文"{电量}，低于低电量阈值 {阈值}%"。电量那一段用 `Level` 的 `Display`，于是写成
"15%（Reported Level），低于低电量阈值 20%"——与悬停提示的电量那一行一字不差。阈值写出来，是因为它可以单台覆盖：用户得看得出
起作用的是哪一个。

**另一条路**：正文只写裸百分比（"电量 15%，低于 20%"），不带"（Reported Level）"。站得住：通知是一瞥就过的东西，
Reported / Derived Level 是项目内部的词，用户在通知里用不上它，而通知比悬停提示显眼得多。

**推荐**：维持——`crate::sources::level` 上写着两个来源要一路带到界面上（混用过一次就导致过错误结论），悬停提示里用户已经在读
这几个字。若要让用户可见的文字统一去掉来源标注，那是悬停提示与通知一起改，不单改这里；通知这一半关在 `src/tray/notify.rs` 的
`low_battery` 与 `tests/tray_notify.rs` 里的字符串。措辞归用户拍板，`/settle` 时问一句。
