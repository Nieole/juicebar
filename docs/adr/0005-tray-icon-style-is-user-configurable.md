# 托盘图标怎么画全部交给用户选，连设计上不推荐的选项也保留

托盘图标与右键菜单有 8 个方面可以有不同的画法：图标画法、数字字形、满电 100 怎么画、灰状态
怎么区分、一次读数都没有过时画什么、充电标记、菜单里写不写来源、Primary Device 标在哪。
**这 8 项全部做成用户设置**，写在 `config.toml` 的 `[tray]` 表里，在右键菜单的"图标样式"与
"菜单显示"两个子菜单里改，点一下立刻生效并按 ADR-0003 格式保留地写回。备选方案是定一个方案
不开放，或者只开放"口味"类的几项；最终选择**全部开放，而且设计审阅里明确不推荐的两个选项
也照样提供**，由用户自己决定。

设计稿与审阅过程在 `.scratch/tray-design/icon-review.html`（2026-09-10 定稿）。

## Considered Options

**定一个方案、不开放设置**，是 README 设计要点原来的路子（"托盘单图标""颜色承载状态"都是
一口说定的）。审阅推翻了它：四个画法各有赢的地方——A 纯数字的数字最大；B 电池的隐喻最直观，
但只在 24 像素以上；C 圆环是量规；D 数字+底条在 16 像素上最好认，因为数字始终是最高对比色，
状态交给底下的条。没有一个在所有尺寸、所有人眼里都最好。

**只开放口味类**（画法、字形、100 怎么画、充电标记），把含义类的固定下来，是审阅时的推荐。
理由是"灰状态怎么区分""没有读数时画什么"定的是**一个符号代表什么**：做成可配置，同一个灰色
"!" 在两个用户那里可能指不同的状态，而 `CONTEXT.md` 刚把取数失败、Unknown、Stale、暂停这几个
概念分清楚。决策者没有采纳，选了全部开放。

**两个有争议的选项**，审阅时建议去掉，决策者决定保留：

- **"满电 100 画成 99"**：它与这个项目最核心的一条规矩相冲突——那一行不许断言它不知道的事。
  保留的理由是：这是用户**自己知情选择**的显示偏好，程序没有背着用户说电量是 99。
- **B 电池在 16、20 像素**：画不下数字（24 像素以上才有），而且取数失败、Unknown、无已知值三个
  状态在它身上长得一模一样。保留的理由是缺陷由选它的用户承担；菜单里那一项旁边写着
  "16、20 像素不显示数字"，选之前看得到。

## Consequences

- **`[tray]` 的 8 个键与它们的取值是对外契约**。发出去之后改名或删掉一个取值，就会让写过它的
  配置读不动。键与取值：
  `style`（`"number"` / `"battery"` / `"ring"` / `"bar"`）、`glyph`（`"block"` / `"fine"` /
  `"system"`）、`full`（`"digits"` / `"cap_99"` / `"block"`）、`gray`（`"one"` / `"split"` /
  `"split_pause"`）、`no_last_known`（`"dash"` / `"question"` / `"outline"` / `"logo"`）、
  `charging`（`"color"` / `"bolt_large"` / `"bolt"`）、`menu_source`（布尔）、
  `primary_mark`（`"both"` / `"radio"`）。
- **默认值才是大多数人看到的样子**：`style = "bar"`、`glyph = "block"`、`full = "block"`、
  `gray = "split"`、`no_last_known = "dash"`、`charging = "color"`、`menu_source = true`、
  `primary_mark = "both"`。
- **含义类的设置意味着符号不再全局统一**。`gray = "one"` 会让取数失败、Unknown、无已知值画成
  同一个符号，Stale 与暂停也分不开；`no_last_known = "question"` 会和 Unknown 的"?"撞在一起。
  这是接受了的代价。
- **原生菜单里放不下解释**（README："原生菜单，零 GUI 框架"）。每个选项为什么这样、代价是什么，
  只写在 `config.toml` 的注释与设计稿里；菜单里唯一的引导是每个选项前面那张按托盘真实尺寸画的
  预览小图。
- **`battery-readout` spec 的那道门槛已经过了**：图标先做成可交互网页给用户审、审过才写渲染代码。
  它留给这一步的问题"完全没有已知值时图标画什么"也有了答案：缺省两道横线，可配置。
- **两处现有文档要等托盘落地时一起改，现在不动**：`config.example.toml` 里 `low_battery` 那条
  注释写的是"图标数字变红"，只在 `style = "number"` 下成立，缺省的 D 是底条变红；`[tray]` 表
  也要到那时才写进 `config.example.toml`——在托盘存在之前写进去，就是一句半真的话（与
  `docs/gaps.md`"用户故事 17 是空的"同形）。
- 设计稿里的渲染器（像素字形、每个画法在每个尺寸上的几何）是 Rust 那一版的参照：Rust 画出来的
  每一档都应当与设计稿逐像素对得上，对不上先查是谁画错了，而不是先改设计稿。
- **下一个读到"画成 99"、想把它当成违反核心规矩去掉的人，看的就是这一条。**它是被权衡过、
  有意保留的。翻案面是一次配置迁移加菜单里的一项。
