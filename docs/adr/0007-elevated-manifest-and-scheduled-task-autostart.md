# 程序清单要求提权，开机自启走"以最高权限运行"的计划任务：不走注册表 Run 键，也不让程序自己提权

走 2.4G 必须是管理员，而权限不够时 Windows 把写静默吞掉，症状和硬件故障分不开（`docs/gaps.md`）。
**决定让 `juicebar.exe` 带一份要求管理员权限的程序清单**（`build.rs`，`requireAdministrator`）：手动
启动就弹 UAC，拒绝就起不来，那是一句明白话。**开机自启走计划任务**：菜单里勾上"开机自启"就建一个
任务——此刻这个用户登录时触发、以他的交互式令牌"以最高权限运行"、启动此刻这个 exe；取消就删掉。
管理员令牌由任务计划程序替它拿，所以开机不弹 UAC。缺省不开；菜单上勾不勾以系统里那个任务在不在为准，
程序不另存一份。

这推翻了 `battery-readout` spec 里"开机自启（注册表 Run 键，默认不开）"的计划。

## Considered Options

**注册表 Run 键**：原计划。被否，因为**需要提权的程序，Windows 登录时不会从 Run 键启动它**——登录时
不弹 UAC 问你，直接不启动。清单与 Run 键不能并存。

**程序不带清单、运行中自己提权，开机自启照旧走 Run 键**：以普通权限启动（Run 键启动得了它），要走
2.4G 时再以管理员身份重启自己。它能保住 Run 键，也不必让命令行子命令跟着提权。被否：自己提权照样是
一个 UAC 框，开机不弹这件事做不到；而"不必让命令行跟着提权"那条好处，随命令行整个取消（spec「成品
形态」、Further Notes）也就没有了。

**同样是计划任务，但起 `schtasks.exe` 去建删**：不是另一个决定，是这个决定的另一种实现，取舍在
parking lot Q320。

## Consequences

- **每次手动启动都弹 UAC**，框里写"未知发布者"（没有代码签名，spec 的 Out of Scope）。开机自启不弹。
- 程序以管理员身份跑，资源管理器不是：权限低的进程发来的消息默认被挡掉（UIPI），托盘图标的回调与
  `TaskbarCreated` 那条广播得放行（`src/shell/mod.rs` 的 `create_window`）。
- 任务计划程序有几项缺省值与"常驻托盘"不合，建任务时改掉（`src/shell/scheduled_task.rs`）：用电池时
  不启动、72 小时后结束任务、优先级低于普通。
- 任务指向**建它那一刻的 exe 路径**。exe 挪了地方，任务还在、菜单照样勾着，开机却起不来；取消再勾一次
  就指向新的路径（parking lot Q324）。
- **开机自启只对管理员账户成立**：任务以建它的那个身份、最高权限运行。普通用户每次输管理员的密码来提权
  时，托盘是以那个管理员的身份在跑，勾上建出的任务也绑在那个管理员身上，普通用户登录时不会触发；而绑到
  普通用户身上，任务计划程序也拿不出一个管理员令牌给它。
- 开机自启时托盘可能比资源管理器先起来：图标加不进通知区的那几秒里要弹的通知，外壳排着等图标加进去
  再弹（`src/shell/icon.rs`，parking lot Q204、Q321）。
- 诊断用的示例程序不带清单（清单只落在 bin 目标上），从没提权的终端里跑照旧是"读超时"；`cargo test`
  也不受清单影响（`Cargo.toml` 的 `[[bin]]` 关了 bin 的单元测试）。
- 翻案面：换回 Run 键，得先拿掉清单、改成运行中自己提权，开机就要弹 UAC。外壳里建删任务的那一个文件
  整个换掉；内核里"开机自启"那一项与"建 / 删"两个动作（`src/tray/launch.rs`）不受影响。
