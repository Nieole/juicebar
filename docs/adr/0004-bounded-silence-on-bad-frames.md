# 设备答坏帧而手上有历史值时，取有界的沉默，不取错误分类

一条 Endpoint 上回来的帧整体不可采信时（读取异常：校验和不对、字段落在物理不可能的值域外），
如果状态文件里还有这台设备的上次已知值，那一行**只显示历史值加"已陈旧，上次已知值"，
不说"设备正在回坏帧"**。备选方案是给取数失败分个类型、让这一支破例把原因印出来；最终选择
**保持沉默**，因为那个分类要穿过每一个驱动的错误路径，而这段沉默是有界的。

## Considered Options

**破沉默**要一个能被 `read_or_last_known` 问的分类（"这一趟是读到了坏帧，还是压根没读到"）。
靠字符串嗅探是不行的——那条路在 Primary 的暂停判定上已经被否过一次。真做就是一个枚举穿过
每个驱动的错误路径，而"外层那句话该怎么说"这件事**已经被 `lost_reason` 已有的三条分支免费
解决了**（试过了都失败 / 一条都不在场 / 一条都没配），这个枚举买不到别的东西。

**保持沉默**的代价看着比实际大，因为读取异常的头号成因是**厂商上位机在抢同一块共享缓冲区**，
而那一维已经在同一行末尾说话了（"已暂停（VGN VHUB.exe 正在运行）"）。剩下的成因（固件变了、
协议对不上）罕见。

## Consequences

- **沉默最多持续到 `very_stale_after`**（缺省一天）。历史值过期后在 `LastKnown::reading_for`
  那一步就被丢掉，于是取数那一趟的真原因照旧印出来。这个失败模式会自己转成可见，不需要人去查。
- 因此这不是"错误被咽掉了"，是"**一天之内先给你一个旧数字，一天之后告诉你出了什么事**"。
  下一个读到这段代码、奇怪为什么一台正在回坏帧的设备安安静静显示旧数字的人，看的就是这一条。
- 哪天真要破这个沉默，代价是那个分类枚举，翻案面是每个驱动的错误路径加 `read_or_last_known`
  一处分支。
