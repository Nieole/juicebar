# 有线连接是一等 Endpoint，照常读取电量

早期共识写的是"有线模式只识别在线并充电中，**不读电量**、不碰协议"，那是在假设有线路径拿不到
电量数据的前提下定的。实测推翻了这个前提：鼠标插线后会**额外枚举出一个设备**
（`391D:1005`，与 dongle 的 `1A05` 并存），它照常响应 cmd 4 并回完整的 level / charging /
voltage。

真正逼我们改的是被动后果：**鼠标插线时 2.4G dongle 会超时**（设备不再经 2.4G 传数据）。若坚持
不读有线，充电中的鼠标就没有任何可用数据源，只能显示离线——而"设备插线时若显示离线是明确的
误报"同样是白纸黑字的共识。不读有线，就必然踩自己定的另一条红线。

因此把有线提升为与 `Dongle24G`、`Ble` 平级的 `Endpoint`，走同一套解析。

## Consequences

- 一个 Device 最多有三条 Endpoint，取数时按 `Wired > Dongle24G > Ble` 依次尝试，遇第一个成功即停。
- 配置多出 `[device.wired]` 块，且它**只在设备插线时才扫得到**——自举时通常缺席，需要
  `juicebar config-refresh` 事后补全。
- 两台设备的插线行为并不一致，判定逻辑不能通吃：鼠标插线即切有线传数据（`1005` 枚举、dongle
  超时）；键盘则要把模式开关拨到有线才枚举 `502F`，仅插线时数据仍走 2.4G 且 dongle 照常应答。
