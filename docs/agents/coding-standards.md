# 编码标准

这个仓库的代码该怎么写。`/code-review` 的 Standards 轴找的正是这种文件：这里写下的每一条都压过
它那份通用的气味基线。

## 用户可见的字符串不折行

**印给用户的一句话，在源码里就写成一行**：它不受列宽约束，一律不折行，**禁止用续行符（行尾的
`\`）去折它**。源码行因此超出仓库惯常的列宽，就让它超出。

"用户可见"指这个仓库里的程序印出去、或替人写进文件里的话：`println!` / `eprintln!` 的格式串、
`bail!` / `anyhow!` 的错误文案、草稿里的注释、**clap 从 `///` 文档注释生成的帮助文本**——`juicebar`
本身与示例程序一样算。测试里的断言文案不算：它只在测试红的时候印给改代码的人看。`concat!` 分段
没有丢字符的风险，但它也是折——一句话不需要第二种写法。

clap 那一种走的是另一条路：它把同一段 `///` 里折开的两行用一个空格接起来，中文句子里那个空格就是
多出来的（`probe --help` 里 `--listen` 那段话曾在逗号后面多一格，parking lot Q133）。所以 `///` 里
印给用户的一句话同样写成一行；那条验收 grep 看不见它（注释行被排掉，空白也只有一格），要靠 review。

**为什么**：这个仓库用续行符折这类字符串栽过两次，两次是同一个样子——续行符丢了，源码里用来对齐
的缩进空格原样印进了那句话中间（一次 22 个，一次 13 个）。续行符在的时候，那句话印得完全正确；
它不在的时候，编译照过、测试照过、那句话照样印得出来，只是中间多了一截空白。**一句用户看得见的
话，其正确性不该挂在一个看不见的字符上。**

**gate 在这一类上两头都没有意见**：`rustfmt` 不折字符串，一行超宽的字符串字面量 `cargo fmt --check`
照样放行——所以不折行在 gate 上没有代价；而丢了续行符留下的那截空格是字符串里合法的内容，`fmt`、
`clippy`、`test` 三条也都看不见它。挡得住它的只有这条规矩和下面那条 grep。

**边界**：管的是一句话——输出里本来就是一行的文字。**有意的多行块不归这一条管**：它们的源码断点
都落在输出的换行处，一行源码就是输出里的一行；断点前若有几格空白，那是下一行要印出去的缩进（草稿里
那几段 TOML 块与注释，`src/config/draft.rs`）。它们的续行符丢了一样会漏空白，但"写成一行"这个解法
对它们用不上，怎么写是另一个问题（parking lot Q112）。

**验收**：

```sh
git grep --untracked -nE '\S {5,}\S' -- '*.rs' | grep -vE '^\S+:[0-9]+: *//'
```

它找的是事故留下的签名：同一行里一截 5 个以上的连续空格，两侧都不是空白。**必须排掉注释行，不能
裸跑**——对齐续写的注释（`//     接着上一行`）长的正是这个样子，裸跑今天就不是零。它扫全部 `.rs`
（包括还没 `git add` 的新文件；被 gitignore 的 `target/` 不扫），**不按目录列**：代码会搬家，一条
只扫 `src tests` 的验收，在文件搬走那天就静静地看不见它了。**它的输出应当是空的**——通过时这条
管道的退出码是 1（`grep -v` 没东西可印），判它看输出，不看退出码。

**它只看得见一种形状**：续行符连同换行一起没了、缩进留在同一行里——两次事故都是这样。另一种形状
（续行符没了、换行还在，那句话断成两行、下一行开头一截空白）在源码里与正常缩进无从分辨，grep 抓
不到；那要靠 review 照规矩本身看：**一句话的行尾出现了 `\`，就是违规**，不论它今天印得对不对。

**这条立下时还有六句旧话用续行符折着**（`src/config/edit.rs` 三句、`src/endpoints.rs`、
`src/sources/vgn_keyboard.rs`、`src/sources/vgn_mouse.rs` 各一句，parking lot Q111）；到第 3 趟
`/settle`（2026-09-15）它们都已展开成一行，下面这条命令今天只列出多行块的开头。谁再折一句，就把它
展开——展开前后输出逐字节相同。要看今天的候选，用这条列，再逐条看——折的是一句话才算，多行块的
开头与测试断言也会被列出来：

```sh
git grep -nE '[\\]$' -- '*.rs' | grep -vE '[\\]n *[\\]$|"[\\]$'
```

（定于 screen-as-a-function 票 02，出处是 parking lot Q79、Q88、Q90：Q79 修掉了 `config-refresh`
那句 Ble 提醒里的 22 个空格，Q88 记下了 `probe` 那句里的 13 个、本票收掉了它，Q90 问的就是这条规矩
本身——一律 `concat!` 分段，还是一律不折。）
