# 编码标准

这个仓库的代码该怎么写。`/code-review` 的 Standards 轴找的正是这种文件：这里写下的每一条都压过
它那份通用的气味基线。

## 用户可见的字符串不折行

**印给用户的一句话，在源码里就写成一行**：它不受列宽约束，一律不折行，**禁止用续行符（行尾的
`\`）去折它**。源码行因此超出仓库惯常的列宽，就让它超出。

"用户可见"指最终会出现在用户眼前的字符串：`println!` / `eprintln!` 的格式串、`bail!` / `anyhow!`
的错误文案、程序替用户写进文件里的话。`concat!` 分段没有丢字符的风险，但它也是折——一句话不需要
第二种写法。

**为什么**：这个仓库用续行符折这类字符串栽过两次，两次是同一个样子——续行符丢了，源码里用来对齐
的缩进空格原样印进了那句话中间（一次 22 个，一次 13 个）。续行符在的时候，那句话印得完全正确；
它不在的时候，编译照过、测试照过、那句话照样印得出来，只是中间多了一截空白。**一句用户看得见的
话，其正确性不该挂在一个看不见的字符上。**

**gate 在这一类上两头都没有意见**：`rustfmt` 不折字符串，一行超宽的字符串字面量 `cargo fmt --check`
照样放行——所以不折行在 gate 上没有代价；而丢了续行符留下的那截空格是字符串里合法的内容，`fmt`、
`clippy`、`test` 三条也都看不见它。挡得住它的只有这条规矩和下面那条 grep。

**边界**：管的是一句话——输出里本来就是一行的文字。**有意的多行块不归这一条管**：源码的每个换行
都正落在输出的 `\n` 上、一行源码就是输出里的一行（草稿里那几段 TOML 块，`src/config/draft.rs`）。
它们的续行符丢了一样会漏空白，但"写成一行"这个解法对它们用不上，怎么写是另一个问题
（parking lot Q112）。

**验收**：

```sh
git grep --untracked -nE '\S {5,}\S' -- '*.rs' | grep -vE '^\S+:[0-9]+: *//'
```

它找的是事故留下的签名：同一行里一截 5 个以上的连续空格，两侧都不是空白。**必须排掉注释行，不能
裸跑**——对齐续写的注释（`//     接着上一行`）长的正是这个样子，裸跑今天就不是零。它扫全部 `.rs`
（包括还没 `git add` 的新文件；被 gitignore 的 `target/` 不扫），**不按目录列**：代码会搬家，一条
只扫 `src tests` 的验收，在文件搬走那天就静静地看不见它了。**它的输出应当是空的。**

**它只看得见一种形状**：续行符连同换行一起没了、缩进留在同一行里——两次事故都是这样。另一种形状
（续行符没了、换行还在，那句话断成两行、下一行开头一截空白）在源码里与正常缩进无从分辨，grep 抓
不到；那要靠 review 照规矩本身看：**一句话的行尾出现了 `\`，就是违规**，不论它今天印得对不对。

**这条立下时还有六句旧话用续行符折着**：`src/config/edit.rs` 三句、`src/endpoints.rs`、
`src/sources/vgn_keyboard.rs`、`src/sources/vgn_mouse.rs` 各一句（parking lot Q111）。续行符都还在，
今天印得对，每一处都只差一个字符就是第三次事故。谁改到其中哪一句，就把那一句展开成一行——展开前后
输出逐字节相同。

那句 Ble 提醒里的 22 个空格，Q88 记下了 `probe` 那句里的 13 个、本票收掉了它，Q90 问的就是这条规矩
本身——一律 `concat!` 分段，还是一律不折。）
