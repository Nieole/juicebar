# 队列约定

一趟实现队列（多张票、多棵 worktree 并行、逐张汇入）里那些不属于任何单张票的规矩。

## base 上的 gate 本来就是红的

**顺手修掉，让 gate 真的绿，并在报告里把这件事说清楚**——修的是哪几个文件、红的原因是什么
（工具链前进带来的新 lint？还是真写错了？）、改动是不是 gate 自己的工具吐出来的。

即使这让这张票动到了不属于它的文件，也照此办。

**为什么**：红着的 gate 是这趟队列的合约破了，它会被后面每一张票各撞一次、每个 agent 各排查
一次。而 gate 自己的工具（`cargo fmt`、`clippy --fix` 那类）吐出来的改动，在 N 棵 worktree 里
逐字相同，合并不会打架——这是"顺手修"在并行下仍然安全的全部依据。

**边界**：只修 gate 指出来的那几处，改动限于空白与等价改写。gate 红的原因若是**真的写错了**、
或者修它要动逻辑，那不是顺手修，那是上报。

（定于第 1 趟 `/settle`，出处是 parking lot Q5：票 01 在 `6d5eb1c` 上撞到两条 clippy 1.98 才有的
新 lint 和三个文件的格式，顺手修了，因此动到了 `src/bluetooth.rs` 与 `src/cli/caps.rs`。）

## 路过的缺陷记下来别顺手改 —— 但票面点名要对齐的那一处不算路过

**默认**：撞见一处与本票无关的缺陷，写进 parking lot，别顺手改。理由是并行下的证据——一张
票的 diff 越是只有它该有的东西，合并时越核得快。

**例外**：**票面自己点名要与之保持一致的那一处，从来就不算路过。** 票面写着"调子照 X 那条
分支"，而 X 自己印的是一句带窟窿的话，那么"照它"这条指示今天只成立一半——不修掉它，本票那一
格就验收不了。这种修改是本票的活，不是顺手。

**边界**：票面、spec 与 `CONTEXT.md` 一个字都没提到的东西，就是路过，照默认办。判它的顺序是
先翻票面，不是先看改动大小——一个字符的修正也可能是路过，一处需要动几行的修正也可能是本票
份内的。

**还有一条推论**：一条"记下来等以后有人回来接"的记录，若没有任何一张票承接它，它多半会一直
挂着。**记之前先问一句这一条归谁**；答不上来的，那正是它该被 `/settle` 结算的形状，不是被
无限期挂起的理由。

（定于第 2 趟 `/settle`，出处是 parking lot Q79 与 Q88：Q79 那处 22 个空格长在票面明令"调子照
它"的那条分支上，当票修掉了；Q88 那处 13 个空格长在票面一个字没提的 `probe` 上，记下来交给
结算。**一张票留下的判据成了下一张票的判决程序**，所以它升到这里。）
